# 임베딩 비교 평가 — Qwen3-Embedding-0.6B vs BGE-M3 (2026-11-09, ADR-0051 D3)

## 방법
- `RetrievalEvalIT`(질문 25개, 정답 문서·정답 절은 11-05 에 원문을 읽어 정한 그대로)를 임베딩만 바꿔 세 번 돌렸다.
  - `./gradlew :services:ai-assistant-service:integrationTest --tests "*RetrievalEvalIT" -PevalOllamaModel=<모델>`
- 색인 대상: manifest 전체 — 파일 75 · 청크 1,966(ADR-0037~0051 추가 뒤라 11-05 의 기준선 0.76 과 수치가 다르다).
- 검색 규칙은 그대로: pgvector 코사인 0.6 + pg_trgm 0.4 혼합, 임계값 0.18, 지위·우선순위 가중(해시 기준선에 맞춰 정한 값 — 바꾸지 않음).
- 모델: PC1 의 임시 Ollama 0.40.10 컨테이너(RTX 2060, 127.0.0.1 만). 둘 다 1024차원·정규화 벡터.
- Qwen3 는 질문에만 모델 권장 지시문을 붙였다(`Instruct: … Query: …`, 문서는 그대로). BGE-M3 는 지시문 없음.

질문별 차이(문서 순위, 절 순위 — "-" = 상위 5 밖): `compare-by-question.txt`. 원 보고서는 같은 폴더의 `*-doc.md`·`*-section.md`.
- Qwen3 만 맞힘: Q12(절 3위). BGE 만 맞힘: Q05(문서 5위, 절은 둘 다 못 맞힘).

## 추천: Qwen3-Embedding-0.6B
- 더 엄격한 절 기준에서 앞선다(0.76 vs 0.68). 문서 기준은 같다.
- 모델이 절반 크기(639 MB) — RTX 2060 6GB 에 대화 모델(4B, 약 3GB)과 함께 올리기 쉽다. 질문 검색도 더 빠르다.

## 한계(결정 전에 알아 둘 것)
- 질문 25개 — 0.76 vs 0.68 은 2문항 차이다. 질문을 늘리면 뒤집힐 수 있다.
- 혼합 가중·임계값이 해시 기준선에 맞춘 값이다. 의미 임베딩에 맞춰 다시 정하면 두 모델 모두 오를 수 있다.
- 색인 시간은 한 건씩 부른 값이다(묶어 보내면 줄어든다). 운영 구현 때 묶음 호출로 한다.
- 운영 연결은 아직 없다 — 이 평가는 시험 전용 `OllamaEvalEmbedding` 으로 했다. 전처리 식별(`preprocessing_hash`)은 char(64) 라 SHA-256 으로 넣어야 한다(짧은 값은 공백이 붙어 스냅숏 비교가 어긋남 — 첫 실행에서 발견).
