# ai-assistant-service 1차 계획 — Codex 3차 검토 (2026-11-04, 원문)

클로드에게는 **"이전 지적은 대부분 반영됐다. 아래 남은 불일치를 수정하면서 local/fake 구현을 진행해도 좋다"**고 답하겠습니다. 이번에도 계획 문서만 검토했으며, 코드와 버전 정보는 별도로 검증하지 않았습니다.

전달할 내용은 다음과 같습니다.

1. **현재 권한 재검사를 모든 저장 답변 반환 경로에 적용해 주세요.**
   지금은 `GET /{answerId}`에만 명시돼 있습니다. requestId 조회, POST 멱등 재응답, 선점을 잃은 작업자의 재조회 응답에도 같은 검사가 필요합니다. 대체 제안 문서를 ID로 추가 조회할 때도 접근 범위 필터를 적용해야 합니다.

2. **출처 허용 목록은 출처 인증과 구분해 주세요.**
   토큰에 `src`가 없으면 호출자가 허용 목록의 다른 값을 선택할 수 있습니다. 따라서 이 방식만으로 "다른 sourceSystem의 결과는 조회할 수 없다"는 보장은 성립하지 않습니다. 1차에서는 `backoffice-web` 하나로 고정하거나, 인증 주체와 허용 출처를 서버에서 연결해 주세요.

3. **스냅숏 삭제와 요청의 스냅숏 고정을 원자적으로 조율해 주세요.**
   D에는 활성 ID를 읽는다고만 되어 있고, PROCESSING 행에 언제 기록하는지가 없습니다. 스냅숏 선택·참조 기록과 삭제 검사 사이의 경쟁을 막아야 합니다. 완료된 답변의 권한 재검사도 스냅숏 삭제 후 가능하도록 접근 범위 메타데이터를 보존하거나, 해당 답변이 남아 있는 동안 스냅숏 삭제를 막아 주세요.

4. **"청크 단위 발췌" 뒤의 앞부분 자르기 규칙을 제거해 주세요.**
   `청크 앞부분 + "… 원문 계속"`은 뒤쪽 조건·예외를 다시 잘라낼 수 있습니다. 길이 제한은 온전한 청크의 개수를 줄이는 방식으로 적용하고, 너무 큰 청크는 조건·예외를 보존할 수 있을 때만 분할해야 합니다.

5. **과거 질문이라고 `EXCLUDED_FROM_PHASE1`을 자동 포함하지 마세요.**
   `SUPERSEDED`는 과거 근거지만, `EXCLUDED_FROM_PHASE1`은 이번 범위에서 제외된 자료입니다. 이력 검색에서는 대체된 문서만 허용하고, 범위 제외 자료는 계속 제외하는 편이 현재 정의에 맞습니다.

6. **구현에 필요한 메타데이터와 상태 처리를 맞춰 주세요.**
   - `proposedSupersededBy[]`와 우선순위 등급의 저장 위치가 스키마에 빠져 있습니다.
   - D의 `question_hash`를 A·C의 `request_hash`로 통일해야 합니다.
   - 활성 색인 부재는 422인데, D의 실패 완료 규칙은 모두 503으로 되어 있습니다.
   - GET에서 lease가 만료된 PROCESSING을 계속 202로 반환하면 조회만 하는 클라이언트가 무한 대기합니다. 같은 키로 POST 재시도를 안내해야 합니다.

**계획을 다시 크게 확장할 필요는 없습니다.** 위 내용을 구현과 회귀 테스트에 반영하고, 완료 보고에는 기준선 평가 결과와 실제 모델 미검증 범위를 그대로 구분해 주세요.
