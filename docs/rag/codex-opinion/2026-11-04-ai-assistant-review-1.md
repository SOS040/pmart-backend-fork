# ai-assistant-service 1차 계획 — Codex 1차 검토 (2026-11-04, 원문)

계획의 큰 방향으로 진행하되, 다음 사항을 반영해서 구현해줘.

1. ADR의 '대체 선언'과 '승인된 대체'를 구분해줘.
   ADR-0025는 현재 파일에 '제안, 사용자 검토 전'으로 적혀 있다.
   본문에 ADR-0019를 대체한다고 적혀 있어도, 그것만으로 기존 결정을
   SUPERSEDED로 바꾸면 안 된다.
   승인 여부, 대체 대상 절, 적용 범위를 확인해 대체 관계를 활성화하고,
   확인되지 않은 관계는 제안으로 유지해줘.
   '제안 ADR이 기존 승인 결정을 폐기하지 않는다'는 회귀 테스트를 추가해줘.

2. 정책 지위와 구현 상태를 별도 메타데이터로 관리해줘.
   CONFIRMED/PROPOSAL 같은 정책 지위와 IMPLEMENTATION_RECORD는
   같은 축의 배타적인 값이 아니다.
   authority, lifecycleStatus, implementationEvidenceDate 등을 분리해,
   승인된 설계이지만 미구현인 경우도 표현해줘.
   날짜가 붙은 '구현 상태'라는 제목만으로 현재 구현을 보장하지 말고,
   답변에는 해당 기록의 기준일을 명시해줘.

3. local 해시 임베딩 + 발췌 모드는 기준선으로 명확히 표시해줘.
   이 모드로 실행·계약·검색 파이프라인은 검증할 수 있지만,
   실제 의미 검색과 생성형 답변 품질 검증이 완료된 것은 아니다.
   응답에 answerMode 같은 식별 정보를 제공해 클라이언트도 구분하게 해줘.
   모델 교체 시 임베딩 캐시는 모델명·차원뿐 아니라
   모델 버전과 전처리 설정까지 구분되도록 해줘.

4. 모델 호출과 DB 트랜잭션 경계를 명확히 설계해줘.
   RequestIdempotency.execute가 여는 트랜잭션 안에서
   임베딩·LLM 네트워크 호출을 오래 기다리는 구조는 피해야 한다.
   그렇다고 모델 호출을 단순히 앞으로 옮겨 중복 호출을 방치하지도 말아줘.
   요청 선점, 처리 중 상태, 완료 결과 저장, 장애 후 재시도·복구를 설계하고,
   같은 키 동시 요청과 최초 응답 유실 테스트를 포함해줘.
   requestId 조회의 식별 범위도 sourceSystem·호출자와 함께 명확히 해줘.

5. 인용 검증 실패 시 잘못된 답변 본문을 그대로 반환하지 말아줘.
   usedIds가 검색 결과에 포함된다는 검사는 인용 ID의 유효성만 보장한다.
   실제로 답변을 뒷받침하는지는 별도 문제다.
   유효하지 않은 인용만 삭제하고 원래 답변을 유지하지 말고,
   제한된 재생성 또는 검증된 발췌 응답으로 전환해줘.
   근거를 확보하지 못하면 NO_GROUNDING으로 처리해줘.
   fake 모델 테스트는 실제 모델의 환각·프롬프트 주입 방어 검증과 구분해줘.

6. FORBIDDEN_SCOPE 판정을 위해 권한 밖 문서를 검색하지 말아줘.
   검색과 모델 입력은 처음부터 허용된 문서로 제한해줘.
   허용된 범위에서 근거가 없으면 NO_GROUNDING으로 처리하고,
   FORBIDDEN_SCOPE는 명시적인 접근 요청을 권한 정책이 거부한 경우처럼
   비공개 문서의 존재를 추론할 필요가 없는 경우로 한정해줘.
   저장된 답변 재조회도 본인 여부뿐 아니라 현재 권한을 확인해줘.

7. 질문 분류는 단어만으로 차단하지 말아줘.
   '취소 처리 절차를 알려줘'는 정책 질문이고,
   'ORD-123을 취소해줘'는 실행 요청이다.
   '재고 몇 개 이하에서 보충하는 정책인가?'도 문서 질문이다.
   ID·명령어 포함 여부만으로 차단하지 않도록 긍정·부정 사례를 테스트해줘.

8. 로컬 실행 경로와 색인 일관성을 구현 범위에 포함해줘.
   기존 공용 Postgres는 바꾸지 않고,
   선택적으로 실행하는 서비스 전용 pgvector compose 구성을 제공해줘.
   pg_trgm을 실제 사용한다면 확장 생성도 마이그레이션에 포함해줘.
   임베딩 차원 검증과 동시 색인 활성화 제어를 구현하고,
   질문 처리 시작 시 선택한 snapshotId를 검색·답변 저장까지 유지해줘.
   dirty 작업 트리는 실제 읽은 파일 해시 목록을 남겨
   HEAD만으로는 재현되지 않는 입력을 식별하게 해줘.

9. 질문 원문 저장은 필요성을 먼저 줄여줘.
   현재 계약에 질문 원문을 다시 보여주는 기능이 없다면,
   원문 대신 해시와 최소 메타데이터만 저장하는 방안을 우선해줘.
   원문 저장이 필요하면 명시적인 설정과 삭제 정책을 마련하고,
   공통 request_record에 복제되는 응답·인용도 보존 정책에 포함해줘.

10. 버전·완료 보고는 실제 검증 결과에 근거해줘.
    Spring AI 버전과 호환성은 공식 문서·저장소의 정확한 URL 및
    실제 Gradle 의존성 해석·컴파일 결과로 확인해줘.
    완료 보고는 다음을 구분해줘:
    - 계약·색인·권한·멱등 구현 및 테스트 완료
    - 로컬 검색 기준선 평가 결과
    - 실제 모델 연결과 답변 품질 검증 미완료 항목

기존 범위대로 PMart Biz 및 클라이언트 수정, LAN 배포,
실제 문서의 외부 전송 없이 진행해줘.
