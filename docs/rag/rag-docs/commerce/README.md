# 커머스 사내 정책 문서 — RAG 원고 (초안)

MD·승인자·고객센터 상담원·운영 관리자가 상품, 가격, 홈 진열, 검색, 리뷰, 고객 알림, 장바구니, 화면 번호에 대해 물을 때 운영자용 RAG 가 근거로 쓸 **직원용 사내 정책 문서** 초안입니다. 고객에게 공개하는 문서가 아닙니다. 상품·가격·콘텐츠·홈 편성·검색 동의어를 백오피스에서 등록하고 승인받는 절차는 `backoffice/06-product-display-search.md` 에 두고, 이 폴더에는 그 결과가 고객 화면과 업무에 어떻게 적용되는지를 적었습니다.

## 넣지 않은 것
- **정하지 않은 값**: 신상품 판정 기간·랭킹 상품 수, 최근 검색어 개수·보존 기간, 인기 검색어 집계 기간·최소 검색자 수, 오타 교정의 "결과 적음" 기준, 상품 화면 "N개 남음" 노출 기준 — 값 없이 규칙만 적음.
- **결정 전·구현 전**: 쿠폰·프로모션·행사 상세(Commerce 부록 C — 1차 제외), 재입고 알림(팀 확인 필요), 리뷰 신고·숨김·작성 보상, 부분 반품 품목의 리뷰 표시, 알림 수신 끄기·야간 발송 제한·문자/알림톡, 구매 상한 승인 예외(미구현), 0원 가격 허용 여부, 한 방향 동의어(새 결정 필요), 장바구니 상품 종류 수·수량 숫자의 표시 기준, 일시품절 상품의 목록 순서(근거 문구에 상태 표시 없음).
- **화면이 아직 없는 것**: 동의어 관리·결과 0건 검색어 화면, 홈 편성 화면 — 규칙만 적고 화면 위치는 적지 않음.
- **다른 문서 몫**: 주문서 금액·배달팁·봉투값·최소 주문 금액의 기준값, 가격 동결 10분, 취소·환불·반품·교환(주문·클레임 문서), 고객 로그인·탈퇴·찜·동의(`customer_app/`), 라이더 알림(라이더 문서), 포장 라벨·인계 절차(`mfc/`).

## 확인 필요
1. **카테고리 단계와 개수**: Commerce 6.6 은 고객 분류를 1·2단계(상위 30·하위 141·노출 경로 151)로 정했으나, 구현은 참고 자료 구조(최대 4단계, ADR-0015 — 상태 "제안")를 따른다. 본문에는 단계 수·개수를 넣지 않고 "여러 카테고리 노출·대표 하나"만 적음.
2. **비회원 장바구니 옮길 때 재검증 범위**: Commerce 4.2(채택)는 가용·가격·배송 조건까지 다시 확인하고 고객 재동의를 받는다고 했으나, 구현은 판매 상태·구매 상한만 확인하고 재고·가격·센터는 막지 않는다(cart 2026-11-19 BR-50 회신). `customer_app/01-signup-login.md` 제8조 3항은 "비회원이 로그인하면 … 합쳐지며, 가격과 재고는 다시 확인합니다"라고 적어 구현과 다르고, 일반 로그인은 자동으로 합치지 않는다는 Commerce 4.2 와도 다르다. 본문(07 제6조)은 구현 기준으로 적음.
3. **일시품절 상품의 목록 처리**: Commerce 6.6 둘째 문단(태그 없음)은 "일시 품절은 목록 마지막·담기 막음"이나, 구현은 검색에서 품절을 거르지 않고(화면에서 표시) 장바구니는 재고로 담기를 막지 않는다. 본문은 구현만 적음.
4. **ADR-0022(비회원 토큰·장바구니 병합)는 상태 "제안"**: 장바구니 문서는 ADR 대신 `cart-service/CLAUDE.md` 의 구현 사실과 Commerce 4.2 만 근거로 씀. ADR 승인 여부 확인 필요.
5. **분할 배송 알림 횟수**: Commerce 15.3 은 "전량 완료 알림은 주문당 1회"이나 ADR-0064 결정 7 은 배송마다 출발·완료 알림을 보낸다. 본문은 ADR 기준.
