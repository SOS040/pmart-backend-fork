# PMart 화면 번호 정책

시행일: 2026년 11월 20일

## 제1조 (목적)
이 정책은 고객 앱, 라이더 앱, 백오피스, 센터 단말 등 모든 화면에서 주문·배송·고객·직원 등을 가리킬 때 쓰는 화면 번호와, 그 번호를 보여 주고 찾는 기준을 정합니다.

## 제2조 (화면 번호와 시스템 번호)
1. 회사의 모든 업무 대상에는 시스템 안에서 쓰는 긴 시스템 번호가 있습니다. 시스템 번호는 바뀌지 않으며, 화면에서 사람이 알아보기 쉽도록 따로 화면 번호를 둡니다.
2. 목록, 표, 지도, 알림, 대화, 링크 글자에는 화면 번호만 보여 줍니다. 긴 시스템 번호를 목록에 보여 주지 않습니다.
3. 상세 화면에는 "시스템 번호" 칸을 접어 두고 복사 버튼을 둡니다. 시스템 번호는 장애 문의나 기록 대조에만 씁니다.

## 제3조 (화면 번호 형식)
| 대상 | 화면 번호 | 예 |
|---|---|---|
| 주문 | 숫자 8자리(무작위, 겹치지 않음) | `74939255` |
| 배송 | 주문번호-순번(같은 주문의 몇 번째 배송인지, 1부터) | `74939255-1` |
| 라이더 | 가린 이름 · 라이더 번호 숫자 6자리(무작위, 겹치지 않고 바뀌지 않음) | `김*수 · 482913` |
| 고객 | 가린 이름 · 고객번호 숫자 6자리(무작위, 겹치지 않고 바뀌지 않음) | `김*수 · 482913` |
| 직원 | 이름 · 사번 | `홍길동 · P2026-00001` |
| 포장 | 포장 라벨 숫자 4자리(2026년 11월 20일 전에 만든 포장은 6자리) | `3051` |
| 포장 인계 | 포장 라벨 번호 + 인계 | `3051 인계` |
| 접수 건 | C-월일-그날의 일련번호 4자리 | `C-1119-0042` |
| 문의(고객·라이더) | Q-월일-그날의 일련번호 4자리 | `Q-1119-0012` |
| 클레임 | 주문번호 + 종류 + 그 주문의 몇 번째 클레임 | `74939255 반품 1`, `74939255 교환 1` |
| 환불 등 클레임 아래의 처리 | 주문번호 + 종류 + 순번 | `74939255 환불 1` |
| 승인 요청 | 번호 없이 종류 · 요청자 · 시각 | `가격 변경 · 홍길동 · 11/19 09:12` |
| 주문 흐름(취소·재발송 등) | 주문번호 + 흐름 이름 | `74939255 재발송` |
| 센터 중지·출고·작업 지시 | 센터 + 종류 + 시각 | `부산진구지점 · 입고 중지 · 11/19 09:12` |
| 후속 처리·교대 인계 | 붙은 대상의 표기 + 종류 | `C-1119-0042 후속 1`, `11/19 오전 교대 인계` |

## 제4조 (표시 규칙)
1. 배송 번호 옆에는 배송 종류(배송, 재발송, 다시 배송, 반납, 회수)를 함께 표시합니다. 같은 주문의 회수·반납·재발송·다시 배송은 순번 2, 3, …이 됩니다.
2. 라이더와 고객은 가린 이름과 번호로 보여 줍니다. 로그인에 쓰는 이메일은 화면에 보여 주지 않으며, 전화번호는 상세 화면에서만 가린 값으로 보여 줍니다.
3. 처리자·결정자 칸 등 직원을 표시하는 곳에는 이름 · 사번을 쓰며, 직원의 시스템 번호를 보여 주지 않습니다.
4. 접수 건과 문의의 날짜는 한국 시간 기준이며, 일련번호는 날마다 1부터 시작합니다. 하루에 9,999건을 넘으면 5자리가 됩니다.
5. 화면 번호를 아직 받지 못한 대상(번호를 매기기 전의 옛 기록 등)은 종류 · 시각으로 보여 주고, 시스템 번호는 상세 화면에서만 보여 줍니다.

## 제5조 (찾기)
1. 찾기 칸에는 화면 번호를 넣어 찾을 수 있습니다. 시스템 번호를 붙여 넣어도 찾을 수 있습니다.
2. 배송 번호(예: `74939255-2`)로 찾을 때는 앞 8자리 주문번호로 주문을 찾은 뒤 순번으로 배송을 고릅니다.
3. 라이더·고객을 찾는 조건은 개인정보 열람 정책을 따릅니다.

## 제6조 (포장 라벨 번호)
1. 포장 라벨 번호는 같은 센터에서 열려 있거나 밀봉된 포장끼리 겹치지 않습니다. 인계되거나 무효가 된 포장의 번호는 다시 쓰일 수 있습니다.
2. 이미 만든 6자리 포장 번호는 그대로 둡니다.
