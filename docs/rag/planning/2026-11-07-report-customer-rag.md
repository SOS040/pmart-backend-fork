## 1. 요약
고객이 앱에서 반품·배송비·취소 가능 여부 같은 **정책**을 물으면, **고객이 읽어도 되는 문서만** 검색해 근거와 함께 답한다. "내 주문 어디까지 왔어?" 같은 실시간 질문은 문서로 답하지 않는다. 운영자용과 서비스·DB·검색 코드를 함께 쓰고, 고객 공개 문서·고객용 API·고객용 분류 규칙을 새로 만든다.

## 2. 운영자용과 같은 것 / 새로 만들 것
| 구성요소 | 운영자용에 이미 있음 | 고객용에 새로 필요 |
|---|---|---|
| 서비스 | ai-assistant-service | — (같은 서비스) |
| DB | RAG 전용 PostgreSQL + pgvector 1개 | 같은 DB. 청크 접근 범위에 "고객 공개" 값, 답변 기록에 질문자 유형(고객·운영자) |
| 처리 단계 | 선점 → 분류 → 스냅숏 고정 → 검색 → 생성 → 인용 검사 → 저장 | 같은 단계. 분류 규칙만 고객용 |
| 검색 | Retriever(WHERE 접근 범위 먼저) | WHERE 접근 범위 = 고객 공개 |
| 임베딩 | EmbeddingModel | 같은 모델(D3 결과) |
| 답변 생성 | Extractive(지금), Generative(결정 대기) | 고객용 모델·지침(짧고 쉬운 말투) — C8 |
| API | 운영자 API | **고객 질문 API(새 계약)** — 본인 질문·답변만 |
| 게이트웨이 | 운영자 JWT | 고객 JWT, 고객별 요청 제한 |
| 문서 | 내부 문서(manifest) | **고객 공개 정책 문서 — 지금 없음** |

## 3. 처리 순서
1. 선점(요청 해시·lease)
2. 의도 분류 — 고객 질문용 규칙
   - 정책 질문(반품·배송비·취소 가능 여부) → 검색
   - 내 주문·배송·재고 → 실시간 질문 처리(4절)
   - 범위 밖 → 거절
3. 활성 스냅숏 고정
4. 검색 — 고객 공개 문서만
5. 생성 — 근거 안에서만 답
6. 인용 검사 → 근거 없으면 `NO_GROUNDING`(고객에게 보일 안내 문구 결정 대기)
7. 완료 저장(질문 원문 저장 여부·보존 기간 결정 대기)

## 4. 실시간 질문
- 1차: 문서로 답하지 않고 거절 + 앱 화면 안내(주문 상세 등).
- 나중(결정 대기): Tool Calling — 고객 본인 토큰으로 order·delivery API 를 **읽기만**. 권한 판단은 그 서비스가 한다. RAG 가 다른 서비스 DB 를 보지 않는다.

## 5. 접근 통제·보안
- 내부 문서(운영 매뉴얼·원가·내부 절차·업무 원문)는 **SQL 에서 빼고, 프롬프트 지시로 막지 않는다.** 검색 후보에도 들어오지 않는다.
- 저장 답변을 돌려줄 때마다 본인·권한 재검사(운영자용과 같음).
- 고객 질문 원문은 개인정보(주소·전화·주문 내용)가 섞일 수 있다 → 저장·보존·로그 정책을 먼저 정한다. 로그에는 지금처럼 본문을 남기지 않는다.
- 고객별 요청 제한(남용·비용 방지).
- 근거 안 지시문(프롬프트 주입)은 데이터로 취급 — 운영자용 생성기와 같은 방식(근거를 태그로 감쌈).

## 6. 고객 공개 문서 적재
| 단계 | 내용 |
|---|---|
| 원본 | 고객 공개 정책 문서 — **지금 없음.** 누가 쓰고 누가 승인하는지 결정 대기(C1) |
| 목록 | manifest 에 문서마다 접근 범위 "고객 공개" 명시 |
| 청크·메타데이터 | 운영자용과 같은 코드(지위·생애·접근 범위) |
| 임베딩 | 검색과 같은 모델 |
| 스냅숏 | 운영자 문서와 함께 / 따로 — 결정 대기(C7) |

업무 원문을 그대로 고객 공개로 넣지 않는다. 고객 문구는 지어내지 않는다 — 원본·작성 주체가 필요하다.
