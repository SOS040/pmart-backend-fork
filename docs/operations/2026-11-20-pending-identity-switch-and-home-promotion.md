## 1. 휴대폰 확인 스위치 + 처리방침 새 판 — 고객 앱 반영 뒤 같은 날 켠다

### 지금 상태
- BR-64 가입·로그인 휴대폰 확인(ADR-0074)은 **LAN에 배포돼 있다.**
  - auth 0.6.0·customer 0.10.0, 이미지 e12d3654, 설정 3e90fb4
- 스위치 `pmart.auth.customer.require-identity`는 **꺼져 있다**(false). 그래서 로그인은 예전과 같다.
- 처리방침 새 판 초안은 `services/customer-service/src/main/resources/consent-terms/PRIVACY_POLICY/2026-11-20.md`(커밋 cc25c00d)에 있다.
  - 담은 것: 휴대폰 번호·확인 기록, 리뷰, OCTOMO 위탁, 탈퇴 후 30일 보관
  - **배포된 이미지에는 없고, 발효도 하지 않았다.**
- 고객 앱(pmart-clients main a8652c87, 11-20 06:50)에는 `AUTH_IDENTITY`·휴대폰 확인 경로를 처리하는 코드가 없다.

### 왜 앱 반영 뒤인가
- 지금 켜면 LAN의 새 가입과 **모든 기존 회원의 다음 로그인이 막힌다.**
  - 확인된 회원이 0명이라 모두 `AUTH_IDENTITY`로 간다. 사용자 결정 (가) "기존 회원도 다음 로그인 때 확인"이다.
  - 그런데 앱에 그 화면이 없다.
- 처리방침과 스위치를 같은 날 켜면 회원은 **로그인 한 번에 "재동의 → 휴대폰 확인"**을 끝낸다. 따로 켜면 두 번 귀찮아진다.

### 켜는 날 순서 (각 단계 사용자 허락)
1. 고객 앱 세션이 "AUTH_IDENTITY·휴대폰 확인 화면 반영"을 알려 온다. 회신: `docs/handoff/clients/customer-app/2026-11-20-reply-br64-phone-identity.md`
2. 처리방침 파일의 **시행일 줄을 그날 날짜로** 고친다. 필요하면 파일·버전 이름도 그날 날짜로 바꾼다. 커밋한다.
3. 그 커밋으로 **customer-service 이미지를 다시 만들어 배포**한다. 본문이 이미지 안에 있다.
4. pmart-config를 고친다.
   - customer `pmart.customer.consents.versions.privacy-policy` → 새 판 버전
   - auth `pmart.auth.customer.require-identity: true`
   - push → 시험 사본 맞추기
5. auth·customer를 재시작한다.
6. 확인한다.
   - 기존 회원 로그인 → `AUTH_CONSENT`(처리방침) → `/completions` → `AUTH_IDENTITY`
   - 휴대폰 확인 → `AUTH_MEMBER`
   - 같은 번호의 다른 계정 → 409 안내

### 남은 할 일 (켜기와 별개)
- 고객 탈퇴를 만들 때 할 것:
  - `customer_identity.released_at` 채우기
  - **30일 지난 번호 지우기**(처리방침 약속)
  - 탈퇴 API는 지금 501이다.
- 처리방침 문구는 실제 서비스에 맞춘 초안이다. 운영 전 법률 검토는 사용자 몫이다.

## 2. 홈 화면 프로모션 — 아직 안 함, 범위 결정 필요

### 지금 홈(storefront) 상태
- 홈에는 "전체 상품" 섹션(`S-ALL`) 하나만 있다.
  - 최근 게시 순이다.
  - 평점·단위 가격이 붙는다.
  - 센터가 취급하지 않는 상품은 뺀다.
- 배너(`banners`)는 늘 빈 목록이다.
- 진열 편성 게시(BO-05, `/storefront/layout-publications`)는 501이다.
- 탭은 HOME 하나뿐이다. `tab=RANKING`은 404다. **고객 앱은 랭킹·신상품 탭을 부르고 있어** 그 화면이 비거나 오류로 보일 수 있다.

### 업무 문서상 범위
| 근거 | 내용 |
|---|---|
| Commerce §1.0(사용자 확정 2026-10-19) | **프로모션·할인·쿠폰은 1차 제외**다. promotion-service는 3단계로 비활성이다 |
| BackOffice BO-05 | 1차에 **일반 배너·상품 테마**가 들어간다. 제목·이미지·연결 대상·노출 기간을 승인받아 게시한다. 할인율·쿠폰·특가가 들어간 배너는 1차에서 게시하지 않는다 |

### 제안 순서
1. **랭킹·신상품 탭**
   - 데이터가 이미 있다. 인기순 순위 신호(ADR-0072)와 최근 게시 순이다.
   - 앱이 이미 부르고 있어 효과가 가장 빠르다.
2. **일반 배너·상품 테마 편성(BO-05)**
   - 백엔드: storefront 편성 초안·발효, approval 전시 승인
   - 백오피스 화면 요청서
3. **할인·쿠폰 프로모션**
   - 1차 제외 결정을 바꾸는 일이다. 사용자 결정이 먼저다(promotion-service, 가격 견적 순서 — service-map pricing·promotion).

### 정할 것
- 사용자가 말한 "홈 화면 프로모션"이 2번(배너·테마)인지, 3번(할인·쿠폰)까지인지 정한다. 1번부터 할지도 정한다.
