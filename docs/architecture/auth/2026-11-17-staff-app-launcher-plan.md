## 2. 지금 이미 되는 것 (확인 2026-11-17)

| 구글 | 우리 | 근거 |
|---|---|---|
| 한 번 로그인 → 모든 앱 | 됨 — Keycloak SSO | employee-auth-service `pmart.employee-auth.apps.*.sso: true`(네 앱 모두 — rider-backoffice 2026-11-17 추가) |
| 다른 앱을 열면 로그인 화면 없이 들어감 | 됨 — 조용한 로그인 확인 | `web/core/src/employeeAuth.ts` `beginSilentEmployeeLogin` → `GET /employee-auth/logins?silent=true` → Keycloak `prompt=none`(`EmployeeLoginService`). 세션 없으면 `?error=LOGIN_REQUIRED` → 로그인 버튼 |
| 한 곳 로그아웃 → 전부 로그아웃 | 됨 | Keycloak 세션 종료(idpLogoutUri) + 다른 앱 세션 끊기(ADR-0061), 탭이 다시 보일 때 확인 |
| 앱 바꾸기 메뉴 | **없음** | 네 웹 앱 코드에 다른 앱으로 가는 링크 없음 — 주소를 직접 친다 |

→ **새로 할 일은 웹 화면의 메뉴뿐이고, 로그인·백엔드는 바꾸지 않는다.**

## 3. 구글과 다른 점 (설계상 받아들임)

1. **처음 열 때 한 번 화면이 넘어간다.** 앱마다 출처(포트)가 달라 토큰·쿠키를 나눠 쓰지 않는다(앱별 PMart 세션 — ADR-0056·0059). 처음 열면
   게이트웨이 → Keycloak → 앱 `/auth/callback` 으로 1초 안팎 다녀온다. 비밀번호는 묻지 않는다.
   - 같은 출처 하나(경로로 나눔 `/hr`, `/mfc` …)로 합치면 이것도 없어지지만, 쿠키·CSP·배포를 다 바꿔야 해서 **하지 않는다**.
2. **조용한 확인은 탭마다 한 번.** 실패하면(Keycloak 세션 없음·만료 12시간) 그 탭에선 로그인 버튼이 보인다 — 정상.
3. **메뉴는 편의일 뿐 권한이 아니다.** 메뉴에 안 보여도 주소를 치면 열리고, 열려도 API 는 서버가 역할로 판정한다.

## 4. 만들 것

### 4-1. 웹 공통 메뉴 (pmart-clients `web/ui`, PC 2 웹 세션)
- 머리줄 오른쪽에 ⋮⋮⋮ 버튼 → 앱 목록(아이콘·이름). 지금 앱은 표시만, 누르면 **같은 탭**에서 그 앱 첫 화면으로(새 탭은 휠클릭·Ctrl).
- **보일 앱 = 네 앱 모두, 모든 직원에게 같게**(사용자 2026-11-17 "다 보여지는 방식"). 역할로 거르지 않는다 — 역할 → 앱 표를 두지 않는다. 역할이 없는 앱을 누르면 그 앱이 이미 띄우는 안내("… 권한이 없어요")가 나오고, API 는 서버가 403 으로 막는다.
- 앱 주소는 **지금 열린 주소의 호스트 이름 + 앱 포트**로 만든다(LAN https 443·8444·8445·8446 — `192.168.0.40`·`d603-16` 어느 쪽으로 열어도 그대로, 개발·목 모드 http localhost 5173~5176). 코드에 IP 를 적지 않는다.
- **로그인·세션 코드(`employeeAuth.ts`·`session.ts` 등)는 건드리지 않는다**(로그인 코드는 PC 1 만 — `pc-split.md` §1-3). 메뉴는 링크만.
- 네 앱 빌드를 같이 확인한다(웹 공통 규칙). 앱 화면 주인은 backoffice·hr-backoffice PC 2, mfc-backoffice PC 3, rider-backoffice PC 5 — 메뉴는 `web/ui` 한 곳(PC 2)에 두고 각 앱은 머리줄에 붙이기만.

~~역할 → 앱 표~~ — 두지 않음(사용자 2026-11-17 "역할마다 보일 앱표를 나눌 필요가 있을까" → "다 보여지는 방식"). 메뉴는 편의일 뿐 권한이 아니고, 네 앱 모두 역할 없는 사람에게 안내를 띄우며, 표를 두면 웹 공통과 각 앱 두 곳에 역할 목록이 생겨(ADR-0068 처럼 화면이 옮겨질 때) 어긋나기 쉽다.

### 4-2. 백엔드 (PC 1)
