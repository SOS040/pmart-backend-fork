# [pmart-backend → pmart-clients] 요청: 인사팀 앱 권한 "연장" 버튼 — 끝나는 날부터 새 요청 (2026-11-18)

- 보낸 영역: platform(PC 1)
- 받는 앱: hr-backoffice(`web/hr-backoffice` 권한 관리) — 담당 PC 2
- 근거: 요청서 `docs/architecture/service-requests/hr-service.md` HR-2 추가 결정 ①(사용자 2026-11-18 "그 내용으로 고치고").
- 계약: 바뀌는 API 없음 — 지금 `POST /hr/employees/{operatorId}/grant-requests`(hr-service 0.6.0~) 그대로. 서버는 기존 권한이 끝나는 날부터 시작하는 같은 권한 요청을 이미 받는다(409 아님).
- 이어지는 문서: `2026-11-17-request-grant-request-validation.md`(센터 칸·이미 가진 권한·409 `GRANT_ALREADY_ACTIVE`), `2026-11-18-notice-center-role-mix.md`.

## 왜
권한 기간을 늘리려고 같은 권한을 다시 요청하면 지금 권한과 기간이 겹쳐 409 `GRANT_ALREADY_ACTIVE`(details `extension=true`)가 난다. 따로 "연장 요청" 종류를 만들지 않고, **지금 권한이 끝나는 날부터 시작하는 새 요청**으로 늘리기로 했다(승인 흐름은 지금과 같음).

## 부탁
1. 권한 관리의 권한 줄마다(끝나는 날이 있는 유효·예정 권한만) **"연장"** 버튼.
2. 누르면 "권한 추가·변경" 요청 칸을 미리 채운다:
   - 역할·센터 = 그 권한과 같게(바꾸지 못하게 하거나, 바꾸면 일반 요청으로 본다).
   - `validFrom` = 그 권한이 끝나는 날. 서버의 권한 끝 `validUntil` 은 "이 시각부터 무효"(마지막 날 다음 날 00:00 Asia/Seoul)라서, **`validUntil` 의 날짜(Asia/Seoul)를 그대로** 시작일로 넣으면 된다(그 전날이 아님).
   - `validTo` = 사용자가 고른 새 마지막 날(비우면 근무 기간까지).
   - 사유 = 사용자가 쓴다(필수 그대로).
3. 409 `GRANT_ALREADY_ACTIVE` 에 `extension=true` 가 오면(사용자가 시작일을 앞당긴 경우 등) "기간을 늘리려면 '연장'을 쓰세요" 안내.
4. 끝나는 날이 없는 권한(기한 없음)은 연장할 것이 없으므로 버튼을 두지 않는다.

## 알아 둘 것
- 승인되면 같은 역할이 **앞뒤 두 줄**(지금 것 + 이어지는 것)이 된다. 회수할 때 둘 다 회수해야 한다 — 권한 목록에서 이어지는 줄을 같은 묶음으로 보이거나, 회수 확인 창에 "이어지는 권한도 있습니다"를 보이면 좋다. (서버가 "회수하면 이어지는 같은 권한도 같이 끝내기"를 할지는 나중에 정한다.)
- 결정 안 된 권한 요청이 있으면 409 `GRANT_REQUEST_PENDING` 은 그대로(한 직원에 열린 요청 하나).

## 상태
- 백엔드 변경 없음 — 화면만 만들면 LAN 에서 바로 된다.
