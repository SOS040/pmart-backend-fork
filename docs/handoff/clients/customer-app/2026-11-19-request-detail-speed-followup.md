## R1. 카드에서 들어갈 때 이미 아는 값을 바로 (요구 3·4)
- 지금은 `/products/{id}` 로 ID 만 넘겨 상세 응답이 올 때까지 로딩만 보인다(`router.dart:296`, 카드 `home_screen.dart:631·653`, `product_list_view.dart:145`).
- 카드가 가진 이름·대표 이미지·가격(·품절 표시)을 상세로 넘겨(예 go_router `extra` 또는 미리 채운 provider) **첫 프레임에 바로** 그리고, 상세 응답이 오면 **가격·재고·옵션·설명을 응답 값으로 덮는다**(카드 값은 화면을 채우는 임시값 — 장바구니 담기·가격 확정에 쓰지 않는다).
- 대표 이미지는 카드와 같은 URL 이면 이미 받은 것이 화면에 바로 나온다(같은 크기 요청이면 메모리 캐시 적중 — 아래 R3 의 `w` 를 카드·상세 대표에서 맞추면 좋다).

## R2. 같은 상품 재진입 캐시·MFC 무효화 (요구 5)
- `productDetailProvider` 가 `autoDispose` 라 화면을 나가면 버리고, 다시 들어가면 매번 새로 받는다. 짧게 붙잡기(예 `ref.keepAlive()` + 몇 분 타이머)를 권한다.
- 키에 지금 MFC 가 이미 들어가 있어(`currentMfcIdProvider` 를 watch) **MFC 가 바뀌면 자동으로 다시 읽힌다** — 이것은 그대로 두면 된다. 캐시된 값을 보여 주면서 뒤에서 다시 읽어 가격·재고는 최신으로.
- 이미지: Flutter 기본 `Image.network` 는 **디스크 캐시가 없어** 앱을 다시 켜거나 메모리에서 밀리면 다시 받는다. 서버는 이미지에 `Cache-Control: private, max-age=31536000, immutable`·`ETag` 를 붙인다(내용이 바뀌지 않는 주소). 디스크 캐시를 쓸지(새 패키지 필요)는 앱이 정해 달라.

## R3. 서버 축소 이미지 — `GET /content-images/{imageId}?w=` (요구 6, 백엔드가 만든다)
- product-content 0.3.0 — **LAN 배포됨 2026-11-19 18:4x(이미지 4350022c)**. 확인(햇양파 설명 이미지): 256KB → 102KB·262KB → 110KB(약 −60%), 원본이 720 이하인 47KB 는 원본 그대로. 처음 요청 0.2~0.5초(만들어 저장), 다음 30~50ms. 계약은 `contracts.lock` 갱신으로 받으면 된다(URL 만 붙이면 되어 생성 코드 변경은 없다). `w` 는 **240·480·720** 중 하나, 원본 비율 유지, 원본 폭보다 작을 때만 줄여 JPEG 로 준다(원본이 그 폭 이하이거나 줄일 수 없으면 원본 그대로). 한 번 만든 것은 저장해 두고 다시 쓴다.
- 권하는 값: 상세 설명·상세정보 이미지 `w=720`, 상세 대표 이미지 `w=720`, 목록 카드 `w=480`(작은 칸은 240). `cacheWidth` 는 지금처럼 그대로.
- 응답 URL 은 그대로(`/api/v1/content-images/IMG-…`) — 앱이 뒤에 `?w=720` 을 붙인다. 붙이지 않으면 지금처럼 원본.
