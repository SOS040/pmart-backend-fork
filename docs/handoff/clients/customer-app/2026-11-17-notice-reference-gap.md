## A. 앱만 고치면 되는 것 (백엔드 준비됨 또는 필요 없음)
| 화면 | 빠진 것 | 참고 |
|---|---|---|
| 주소 | **저장한 주소 수정·삭제** | 백엔드 `PATCH`·`DELETE /me/addresses/{addressId}`(customer-service) 있음. 앱 `address_controller` 는 추가·선택만 |
| 주소·주문 | 라이더 요청사항 자주 쓰는 문구, 주소 검색 예시 문구 | 지금 자유 입력만 |

| 카테고리 | "맛있는 것 / 편리한 것" 묶음 제목, 인기·신상 바로가기 | `CategoryNode.section` 값 이미 있음 |
| 검색 | 결과 아래 장바구니 요약 바, 필터 값을 결과 위에 바로 | |
| 목록 | "더 보기" 대신 자동 다음 페이지 | |
| 장바구니 | 단계별 버튼 문구(최소 금액 → 방법 → 시간 → 주문하기) | |

| 기타 | 로고 스플래시 | 지금 Flutter 기본 |

## B. 백엔드가 먼저 필요한 것 (PC 1 이 계획 — 준비되면 따로 알림)
| 기능 | 백엔드 상태 |
|---|---|
| 실시간 ETA·실시간 위치 | 앱 구현 있음. delivery-tracking-service `GET /deliveries/{id}/eta`·`/stream` **501** |
| 최근 검색어 | search-service `/me/recent-searches` **501** |
| 인기 검색어 | `GET /search/suggestions` 의 `popular` 가 항상 빈 목록 |
| 반품·교환 신청 전체(상품·수량, 사유 3분류, 사진 필수, 교환 불가 목록, 비용 미리 보기, 회수 요청사항) | claim-service 결정·철회 501, 신청 대상·증빙 업로드 API 없음(BR-07·BR-15) |
| 앱 푸시(준비 중·배달 시작·도착·완료) | 푸시 토큰 등록 API 없음(BR-09) — 앱도 푸시 라이브러리 없음 |
| 리뷰 작성 알림·문의 답변 알림 | 알림 종류 없음 |
| 장바구니 최소 주문 금액 진행 바 | 장바구니·`/delivery-options` 에 부족 금액 없음 |
| 주문 내역 카드의 상품명·썸네일·배송 방식, 검색·기간 필터, 주문 내역 삭제 | `OrderSummary` 필드·API 없음 |
| 현금영수증 | BR-17 |
| 품절 처리 "다음에도 적용" | BR-21 |
| 배달 지연 제보, 오배송 확인(배달 위치 사진·라이더 통화 요청) | 고객용 API 없음 |
| 상담원 실시간 채팅, 만족도 조사, 문의 사진 첨부 | 없음 |
| FAQ 검색 | customer-assistant-service FAQ 쓸 수 있는지 확인 필요 |
| 단위 가격("100g당") | BR-19 미정 |
| 배송 지도(매장·도착지) | 고객용 매장 위치 API 없음 |

## C. 정책 결정이 먼저 필요한 것 (사용자 결정 대기 — 만들지 마세요)
- 현재 위치로 찾기·위치 권한 요청, 약관의 위치 서비스·마케팅 푸시 동의와 결과 팝업.
- 장바구니 안 매장 도착 시간·공지, "N원 더 담으면 배달팁 0원", 안심번호·연락처·이메일, 주문 주의사항 동의.
- 추천(함께 담으면 좋은 상품·비슷한 상품·방금 본 상품과 비슷한 것).
- 판매 매장 이름, 카드의 남은 수량, 장바구니 아이콘 숫자, 신선보장·사전예약 배지, 고객센터 전화·운영 시간·전화 상담, 약관·정책 화면.
- 라이더 위치 지도 — 지금 계약은 고객에게 라이더 좌표를 숨긴다.
- 주류(목록 제한·연령 확인) — 주류 판매 여부부터 미정, 자체 본인인증은 만들지 않음.
