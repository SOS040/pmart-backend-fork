## BR-67 리뷰관리 (review-service 0.5.0)
- `GET /me/review-eligibilities` 응답에 `total`(지금 거르기 — orderId·state — 의 전체 수, 쪽 크기 아님)과 **`counts: {writable, written}`**(탭 머리 숫자 — state 와 상관없이, orderId 는 따름. writable = 쓸 수 있음, written = 쓴 리뷰(삭제 제외)).
  - `GET /me/reviews` 는 계약에 없다(앱은 자격 목록의 `reviewId` 로 "내가 쓴 리뷰"를 만든다) → **"내가 쓴 리뷰 N개" 는 `counts.written`** 을 쓴다.
- `Eligibility` 에 (모두 null 가능 — 모르면 비움, 지어내지 않음)
  - `orderedAt` — 주문 확정 시각, `mfcName` — 주문 담당 센터 이름(order 0.15.0 과 같은 값)
  - `imageUrl` — **지금 상품의 대표 사진**(사용자 결정, 주문 당시 사본 아님) `/api/v1/content-images/{id}` — `?w=` 축소 가능. 게시 안 된 상품은 null
  - `optionLabel` — 지금 그 SKU 의 옵션 표시(주문 당시 값은 주문에 없음)

## BR-68 주문내역 카드 (order-service 0.17.0)
- `GET /orders` 의 `OrderSummary` 에 `lines`(앞 **5개**, 주문 행 순서 — `orderLineId·productId·sku·productName(사본)·optionLabel(사본, 없으면 null)·quantity·lineAmount`(단가×수량, 할인 나눔 전)), 전체 수는 기존 `itemCount`.
- `mfcName`(상세와 같은 값, 모르면 null).
- R3(지금 살 수 있는지)은 **이번에 넣지 않음**(사용자 결정 — 목록 품절 표시와 함께 재고 조회 방식을 정할 때). ⊕ 담기는 지금처럼 장바구니 서버 판정.
- 조회 기간 끝 `to` 는 **0.12.0 부터 이미 있다**(서울 날짜, 포함, `from > to` 400) — 시작월·종료월 시트에 그대로 쓰면 된다.

## BR-70 네이버 프로필 사진 (auth 0.10.1) — (나)
- `POST /auth/naver-token-exchanges` 200 에 선택 **`profileImageUrl`** — 서버가 교환 때 받은 access token 으로 네이버 프로필 API 를 한 번 불러 얻은 `profile_image`(https·`*.pstatic.net` 만). access/refresh token 은 여전히 앱에 주지 않고 저장하지 않는다.
- 없으면 `null`(빠지는 게 아니라 null 로 온다 — 같게 다뤄 주세요). 프로필 조회가 실패해도 교환은 200.
- 앱은 받은 주소를 메모리에 두고 지금 계약(0.8.0)의 로그인 본문 세 곳 `profileImageUrl` 에 그대로 실어 보낸다. 같은 Idempotency-Key 재전송은 같은 사진 주소.
- 탈퇴 재인증처럼 로그인이 아닌 교환에서는 사진을 보내지 않아도 된다.
- 네이버 콘솔 "제공 정보 — 프로필 사진" 체크는 **그대로 필요**(사용자 몫 — 없으면 null).
- 라이더 앱(rider-auth 0.3.0)은 해당 없음(라이더 프로필 사진 기능 없음).
