# 요청 — 소셜 닉네임 칸(`providerNickname`)·이름은 실명만

보낸 영역: platform
받는 앱: customer-app
작성: pmart-backend, 2026-11-25
상태: **서버 구현(auth V10·customer 0.19.0) — LAN 배포 전**

## 바뀐 것 (사용자 2026-11-25 "실제 이름과 닉네임 다르게 관리", "이름은 무조건 입력하게 하는데(고객앱 구현됨) 별명만 기존 이름으로 채워넣는걸로")
| 로그인 | `GET /me` `name` | `GET /me` `providerNickname`(새 칸) |
|---|---|---|
| 구글 | 구글 이름 | 구글 이름(구글은 닉네임이 없다) |
| 카카오 | **비어 있음**(카카오는 실명을 주지 않음 — 지금까지 서버가 닉네임을 넣던 것 멈춤) | 카카오 닉네임 |
| 네이버 | 네이버 이름(`response.name`)만 — 별명으로 채우지 않음 | 네이버 별명, 없으면 이름 |

- `nickname`(고객이 앱에서 정한 별명)은 그대로.
- 로그인마다 최신 값, 사건에 없으면 기존 값 유지 — 배포 전 가입자는 다음 로그인부터 `providerNickname` 이 채워진다. 이미 서버가 카카오 닉네임을 `name` 에 넣은 계정은 그 값이 남는다(LAN 카카오 ACTIVE 2명은 `name` 비어 있음).

## 앱에 부탁
1. 표시 이름: `nickname` → `providerNickname` → `name` 순.
2. 이름이 없으면 입력받는 흐름(이미 있음)은 `name` 만 보고 판단 — `providerNickname` 이 있어도 이름으로 쓰지 않는다.
3. 배송지 받는 분 기본값은 실명(`name`)만.

## 같이 바뀐 것 — 네이버 동의 화면
- 서버가 네이버 로그인 교환 때(가입을 마치기 전) 연결을 끊던 것(BR-79 SIGNUP_PENDING)을 없앴다 — 가입 뒤 첫 로그인·탈퇴 재인증에서 네이버 동의 화면이 또 뜨던 원인. 이제 동의 화면은 처음 가입·탈퇴 뒤 재가입 때만. 앱 변경 없음.
- 구글은 앱 `abandonSignup`(가입 중 나감)·탈퇴 때만 `disconnect` — 그 밖에 동의 화면이 뜨면 언제인지 알려 주세요.
