# 요청 — 로딩 화면 이미지 갱신 방식·팝업 창 크기

보낸 영역: platform
받는 앱: customer-app
작성: pmart-backend, 2026-11-21 — 사용자 "로딩화면은 안 바뀌고 팝업 이미지도 안 줄었다", 요청서 보내 달라("응 요청서 보내줘")

## 지금 서버 상태(LAN, 홈 편성 layoutVersion 6 — 2026-11-21 승인·반영)
- `GET /storefront/banners?placement=SPLASH` → `B-SPLASH` 1개, 이미지 941×1672(세로, 사용자 이미지 "오렌지빛 P마트 신선배송").
- `GET /storefront/banners?placement=POPUP` → `B-POPUP-ICE` 1개, 이미지 **1000×1250(4:5)**, 링크 SECTION `T-WEEKEND-ICE`, 끝 2026-11-22T14:59:59Z.
- 둘 다 서버는 새 값을 주는데, 실기기에서 로딩 화면이 예전 그대로이고 팝업 크기가 그대로라고 사용자가 확인했다.

## 요청
- **R1. 로딩 화면(SPLASH)**
  - 지금 앱이 SPLASH 배너를 어떻게 쓰는지 알려 주세요: (a) 앱 실행 때 받아 그 실행에 바로 보이는지, (b) 받아 두었다가 **다음 실행**에 보이는지(보통 방식), (c) 네이티브 기본 스플래시만 쓰고 서버 값을 아직 안 쓰는지.
  - 권장: (b) — 실행마다 `GET /storefront/banners?placement=SPLASH` 로 받아 이미지까지 내려 받아 두고, 다음 실행의 로딩 화면에 쓴다. 기간(startsAt·endsAt)이 지난 것은 쓰지 않고, 서버 목록이 비면 저장분을 지워 기본 화면으로 돌아간다. 이미지 URL 이 바뀌면(imageId 가 다름) 새로 받는다.
  - 로딩 이미지는 세로(약 9:16) — 화면을 채우되 글자가 잘리지 않게 `contain`(여백은 이미지 가장자리 색) 또는 가운데 기준 `cover`, 앱이 정해 알려 주세요.
- **R2. 팝업(POPUP)**
  - 팝업 창 크기를 **화면 폭의 약 80%, 이미지 비율 4:5 고정**(이미지 위 둥근 모서리, 아래 [오늘 하루 보지 않기]·[닫기])으로. 이미지는 창 안에 `contain`.
  - 이미지를 누르면 `linkType`·`linkRef` 로 이동(SECTION 이면 그 테마 영역).
  - "오늘 하루 보지 않기"·이미 본 기록은 **bannerId + imageId** 기준으로 해 주세요 — 같은 팝업이라도 이미지가 바뀌면 다시 보이게(지금처럼 이미지 교체가 안 보이는 일을 막음).
- **R3.** 시험을 위해 개발자 메뉴 등에서 팝업 "다시 보기"(저장 기록 지우기)가 있으면 좋다(선택).

## 회신 부탁
- R1 의 지금 방식과 바꾼 뒤 방식, R2 반영 여부. 서버 변경이 필요하면(예: 배너에 이미지 크기·버전 필드) 알려 주세요.
