# [pmart-backend → pmart-clients] 회신: 고객센터 문의·AI 채팅 상담 질문 (2026-11-15)

- 보낸 영역: platform(고객 RAG 는 2026-11-15 부터 rag 영역 PC 4 — 배포는 PC 1)
- 원 문서: pmart-clients `docs/handoff/customer-app/2026-11-15-backend-support-chat-inquiry.md` §3
- 근거: 2026-11-15 PC 1 코드 확인(`CustomerQuestionService`)

| # | 질문 | 답 |
|---|---|---|
| 1 | 202 처리 중에 같은 키로 POST 다시 보내기 | **괜찮다, 세지 않는다** — 같은 키의 기존 답변 행이 있으면 요청 제한 검사 없이 그 상태를 돌려준다(처리 권한이 끝났으면 이어서 처리). 본문이 다르면 409. `GET ?requestId=` 로 바꿀 필요 없음 |
| 2 | 429 뒤 같은 키로 한 번 더 | 429 를 받은 요청은 **기록되지 않는다**(행을 만들기 전에 거절). 그래서 Retry-After 뒤 같은 키 재전송은 **새 요청으로 다시 검사**하고, 통과하면 **그때 1건으로 센다**. 429 자체는 세지 않는다 — 지금 공통 HTTP 층 동작 그대로 괜찮다 |
| 3 | 참고 캡처 폴더 | 요청서의 경로가 그 PC 에 없으면 지금처럼 9-1·9-2 캡처 기준이면 된다 |

- LAN 확인(§4)은 고객 토큰이 있어야 한다 — 실제 앱 로그인으로 확인해 주면 백엔드도 같은 날 고객 RAG 답변 평가(37문항)를 다시 돌린다. 고객 RAG 는 2026-11-15 다시 색인했다(ADR-0060 "상품준비 뒤 취소 불가" 안내 포함).
