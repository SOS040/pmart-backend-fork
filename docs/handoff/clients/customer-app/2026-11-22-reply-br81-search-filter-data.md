## Q1 어느 쪽을 쓰나 — 지금처럼 `GET /search/filters`
- 카테고리 목록·검색 결과 모두 `GET /search/filters?categoryId=&q=` 를 그대로 쓰면 된다. 이 응답이 패널의 이름·선택 방식·옵션 순서에 **지금 조건의 건수**를 붙이고, 상품이 없는 옵션은 뺀다.
- `/categories/{id}/filters` 는 패널 정의 원본(건수 없음) — 백오피스·참고용.
- **0.7.0 바뀐 것**: 카테고리마다 따로 정의된 같은 이름의 그룹("중량"·"개당 수량" 등)을 한 줄로 묶었다. 그래서 `key` 가 `n:중량` 같은 모양이 됐다(이름에 `.` 이 있으면 그룹 id 그대로). **key 는 받은 그대로 `filters=<key>.<value>` 로 돌려보내면 된다** — 앱이 지금 하는 그대로라 바꿀 것 없다. 하위 카테고리 상품의 그룹 이름이 `filter_…` 로 보이던 것도 고쳤다.

## Q2 가격대 — 앱이 정한다
- 서버는 가격 구간을 주지 않는다. 앱이 정한 구간으로 `minPrice`·`maxPrice`(원, 양 끝 포함, 기본가 기준 — 할인가 아님)를 보내면 된다.

## 함께 한 것 — 원산지 필터·설명 검색 (products-v8)
- `/search/filters` 에 **원산지** 줄: key `origin`, 값 `국내산`·`수입산`(적힌 원산지가 모두 국내면 국내산, 하나라도 외국이면 수입산. 원산지가 없거나 판단할 수 없는 상품은 어느 쪽에도 없다). 거르기 `filters=origin.국내산`.
- 검색어가 상품명에 없어도 **원산지·상품 설명**에 있으면 찾는다("국내산 삼겹살", "칠레산", 설명 속 낱말). 상품명으로 찾은 상품이 늘 앞이다.
- 앱 변경 없음 — 원산지 줄은 다른 속성 줄과 같은 모양(FilterAttribute)이다.

## 하지 않은 것 — 영양 정보
- **영양 정보(열량·당류·단백질 등)는 검색·필터에 넣지 않았다**(사용자 결정 2026-11-22). "저당·고단백·저칼로리" 같은 말은 식품 표시 법적 기준이 있는데, 지금 영양 값은 상품 이미지에서 읽은 것이라 신뢰도가 고르지 않다(중간·낮음 216개). 이 값으로 계산해 붙이면 잘못된 표시가 될 수 있다.
- 그래서 참고 자료 패널에 있는 "열량 1회/100g(ml)당"·"저칼로리 여부" 같은 그룹은 **값이 없어 화면에 나오지 않는다**(빈 그룹은 /search/filters 가 내지 않는다).
- 제조사가 상품명에 쓴 "저당"·"제로"·"고단백" 은 지금도 검색어로 찾힌다. 상품 상세의 영양 표시(notices)는 그대로 보인다.
