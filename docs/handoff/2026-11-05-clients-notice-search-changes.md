## 1. 승인 속성 필터가 실제로 적용된다 (2026-11-04 22:40 LAN)

**`GET /search/products` 의 `filters`**
- 이전에는 계약에만 있고 무시됐다. 이제 실제로 거른다.
- 형식은 반복 파라미터 `그룹.옵션`이다.
  - 예: `filters=seed-storage.냉장&filters=seed-storage.냉동`
- 같은 그룹 안의 값은 OR, 그룹끼리는 AND 다.
- 최대 30개다. 형식이 틀린 값은 버린다.
- 응답의 `appliedFilters` 가 실제로 적용한 값이다. 화면의 선택 표시는 이것을 기준으로 한다.

**`GET /search/filters`**
- 이전에는 늘 빈 목록이었다. 이제 지금 조건(`q`·`categoryId`)에 걸리는 상품의 필터 값과 건수를 돌려준다.
- 응답 모양: `attributes[{ key, label, multiSelect, values[{ value, label, count }] }]`
- `label`(예 "보관방법")·`multiSelect`·값 순서는 product-service 카테고리 필터 패널에서 온다.
  - 그 카테고리와 상위 카테고리의 패널을 합친다.
  - `categoryId` 가 없으면 최상위 카테고리들의 패널을 합친다.
  - 2026-11-04 23:44 부터 카테고리 없이 불러도 이름이 나온다. 그 전에는 키(`seed-storage`)가 보였다.
- 건수가 0 인 값은 나오지 않는다.
- `mfcId` 는 아직 건수에 반영하지 않는다(미취급 상품도 센다).

**지금 LAN 데이터**
- 필터 그룹은 `seed-storage`(보관방법) 하나다.
- 옵션이 붙은 상품은 시험용 두부 1개(`냉장`)뿐이다.
- 필터가 실제로 쓸모 있으려면 **상품 등록·변경 초안의 `filterOptions`** 를 채워 승인해야 한다.
  - product-service 계약에 이미 있는 필드다.
  - 일괄 등록·백오피스 화면에서 이 값을 넣을 수 있는지 확인을 부탁한다.
  - 이전에 승인된 상품은 변경 승인이 새로 나와야 필터가 붙는다.

## 2. 센터 취급 여부 (`mfcId`, `includeNotCarried`, `carried`, `total`) — 2026-11-05 06:15 LAN

| 항목 | 이전(BR-47, 2026-11-04) | 이제 |
|---|---|---|
| 미취급 거르기 (`includeNotCarried=false`, 기본) | 서버가 결과를 받은 뒤 미취급을 빼고, 모자라면 최대 5번 더 읽어 채움. 빈 페이지 + 다음 커서가 올 수 있었음 | 검색 색인에서 바로 거른다. 페이지는 `size` 만큼 차고, 빈 페이지 + 다음 커서는 오지 않는다 |
| `total` | 미취급을 빼기 전 건수(처음부터 끝까지 다 읽은 경우만 정확) | **거른 뒤 정확한 건수** |
| `carried` (`mfcId` 를 줄 때) | `true` / `false` / `null`(불명 — 조회 실패·응답 없음) | **`true` / `false` 만**. 센터 운영자가 취급을 켜지 않은 상품은 `false` |
| `carried` (`mfcId` 가 없을 때) | `null` | `null` (같음) |

- 판정 기준은 상품의 **대표 SKU**다. 지금 LAN 상품은 모두 상품 하나에 SKU 하나다.
- 취급 여부는 mfc-inventory 취급 변경의 색인 사본이다. 센터 운영자가 바꾼 뒤 **몇 초 늦게** 반영될 수 있다.
- **품절은 색인하지 않는다.** 미취급과 품절은 다른 사실이다(업무 문서 Commerce 6.1·6.17). 품절·가용 수량은 지금처럼 상품 상세·담기 때 확인한다.
- 화면이 미취급을 "구분 표시"하려면 지금처럼 `includeNotCarried=true` 로 받아 `carried=false` 를 표시하면 된다(권장 그대로).
- 클라이언트에서 할 일:
  - BR-47 회신에 맞춰 "빈 페이지인데 다음 커서가 있으면 계속 조회"를 넣었다면, 그 코드는 그대로 둬도 된다. 이제 그런 응답이 오지 않을 뿐이다.
  - `carried == null` 을 "불명"으로 표시하던 곳이 있으면, `mfcId` 를 준 요청에서는 더 이상 `null` 이 오지 않는다.

## 3. 검색어 처리 — 띄어쓰기·초성 (2026-11-05 06:15 LAN)

- **띄어쓰기**: 붙여 쓴 검색어가 띄어 쓴 상품명을 찾는다(예 "생크림" → "동물성 생 크림 500ml"). 그 반대는 원래 됐다.
- **초성 검색**: 검색어가 **한글 자음만 2자 이상**이면 상품명 초성으로 찾는다.
  - 예: "ㄷㅂ" → 두부, "ㅅㅋㄹ" → 생크림
  - 자동완성(`/search/suggestions`)도 같다.
  - 자음 1자("ㄷ")와 자음·완성 글자가 섞인 검색어("ㄷ부")는 일반 검색이다.
  - 클라이언트 변경은 필요 없다. 입력한 그대로 보낸다.

## 4. 결과 순서 (2026-11-05 06:55 LAN, `products-v5`)

- **낱말 순서**: 검색어 낱말이 그 순서로 붙어 있는 상품이 위로 온다.
  - 예: "콜라 제로" → "콜라 제로 500ml" 이 "제로 … 콜라맛" 보다 위
  - 찾는 범위는 그대로다.
- **초성**: 낱말 앞부분의 초성이 맞는 상품이 위로 온다.
  - 예: "ㄷㅂ" 첫 결과가 "국산콩 두부". 전에는 "단백질과자…"가 먼저였다.
  - 2자 초성은 여전히 결과가 많다("ㄷㅂ" 28건).
- 같은 검색어라도 이전과 순서가 다를 수 있다. 순서를 고정값으로 기대하는 화면 시험이 있으면 갱신이 필요하다.
