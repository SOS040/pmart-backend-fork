# [공지] 피킹 방문 순서 — 실서버 모드의 가상 작업자도 이 순서로 걸어 주세요 (2026-11-09)

- 규칙(사용자 결정, ADR-0050): **냉장 B → 냉동 A → 상온 C → D → E → F → G → H** 그룹 순(MFC 문서 1장 8-3 원본 순서 — 시뮬레이터 `pickSequence: 'DOC_B_A_C'` 와 같은 그룹 순), **그룹 안은 걷는 거리 최단**(mfc-capacity OR-Tools 경로, 칸 좌표 = 이 평면), 출발은 장바구니 보관 자리(`CRT-A-01` 좌표). 작업자 위치에 따른 예외 없음.
- 실서버: 피킹 시작(`POST /tasks/{id}/starts`) 뒤 `GET /tasks/{id}` 의 `lines[]`·`picks[]` 가 방문 순서, `picks[].visitSeq`·`routeMethod`(fulfillment 0.4.10).
- 시뮬레이터가 맞출 것: 실서버 모드에서는 시뮬레이터의 `routeOrder`(구역 순 + 가장 가까운 칸) 대신 **받은 visitSeq 순서**로 가상 작업자를 걷게 한다. MOCK 모드의 `DOC_B_A_C` 는 그대로 두면 된다(같은 그룹 순).
- 거리: 지금은 칸 서는 지점 사이 직각 거리(벽 미반영). 시뮬레이터의 격자 길찾기(navgrid)와 실제 걷는 길이는 다를 수 있다.
