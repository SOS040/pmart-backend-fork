# ADR-0086 고객 오배송 문의 → 채팅에서 다시 보내기·환불 선택 → 주문 종결, 회수 포기 시 라이더 정산 차감

- 상태: **승인** (2026-11-24, 사용자)
- 보탬: ADR-0052(오배송 회수·새 발송), ADR-0065(오배송 귀책·고객 선택 RESHIP/REFUND), ADR-0069(전달 실패 재발송). 그 결정들은 그대로 두고 **시작하는 길(고객 문의)·고객 선택·기한·라이더 차감**을 더한다.
- 근거(사용자 2026-11-24, PC 5 라이더 앱 세션이 옮김): "라이더가 그럼 오배송 해놓고 전달완료 눌러서 상품을 못 받았다는 거잖아. 그럼 고객이 오배송으로 문의를 남기기 편해야 하고 오배송 문의를 처리하는 UI도 바로 구축이 되어있어야 해. 문의가 들어왔을 때 채킹에서 자동으로 다시 보내거나 취소환불 할지를 선택하게 해서 배송이랑 주문 상태를 종결하게 해. 하루 지나면 회수 배송 포기하고 라이더 귀책으로 고객 주문금액 만큼 정산금 차감"
- 세부(사용자 2026-11-24, PC 1 질문에 답): ① "채킹" = **문의 채팅 안에서 고객이 고른다** ② 차감 금액 = **결제 금액(배달비 제외)** ③ 한 건 정산금보다 크면 **다음 정산으로 넘긴다** ④ **차감 전 라이더 이의 가능, 기한 5일** ⑤ 고객이 고르지 않으면 **5시간 뒤 자동 환불**.
- 계기: LAN 주문 28767701 — 실패 재발송이 오배송됐는데 주문이 "일부 도착·배달 중"에 남고 고객 취소 문의를 처리할 길이 없었다(수량 버그는 0ae3a416 에서 따로 고침).

## 결정
1. **고객 문의로 시작**: 고객 앱 주문 상세(배달 중·배달 완료)에서 "상품을 못 받았어요(오배송)" → case `POST /inquiries` `category: DELIVERY`, `deliveryIssue: NOT_RECEIVED`, `orderId`·`deliveryId`. 지금 NOT_RECEIVED 는 상담원 문의일 뿐이지만, 이제 **배송이 전달 완료(COMPLETED)된 고객 배송(FORWARD·RESHIPMENT)** 을 가리키면 case 가 오배송 사건(MISDELIVERY)을 **자동으로** 열고 고객 선택을 기다린다. 배송이 아직 전달 전이면 지금처럼 상담원 문의(DELAYED 와 같은 취급).
2. **채팅 안에서 고객이 고른다**: case 가 그 문의 채팅에 **선택 메시지**(다시 보내기 / 취소·환불, 기한 표시)를 넣고, 고객이 채팅에서 고르면 `resolution` = `RESHIP` 또는 `REFUND`. 고르는 순간 case 가 `MisdeliveryConfirmed`(fault **RIDER**, resolution, `source: CUSTOMER_INQUIRY`, `inquiryId`, `orderId`) 를 낸다 — 직원 확인 없이. 이후는 기존 길: dispatch 회수 배차(DD-2), orchestration 재발송 사가 RESHIP(다시 보내기) 또는 REFUND(전 품목 환불 — ADR-0065 그대로).
3. **5시간 기한**: 문의 접수(선택 메시지) 뒤 5시간 안에 고르지 않으면 case 가 **자동으로 REFUND** 로 확정(`autoResolved: true`)하고 채팅에 알린다. 그 사이 상담원이 고객 대신 고를 수 있다(직원 화면, 기록 남김).
4. **주문·배송 종결**: RESHIP 은 재발송이 전달되면 주문 COMPLETED, REFUND 는 환불 사가가 끝나면 주문 종결(수량상 COMPLETED — 환불 금액은 claim). 오배송된 배송 자체는 이미 COMPLETED. 회수 배송은 회수(반납)되거나 **24시간 뒤 포기**(dispatch, PR #416 — `DeliveryCancelledBeforePickup` reason `RECOVERY_ABANDONED`)로 닫힌다. 고객 화면에 "일부 도착·배달 중"이 남지 않아야 한다.
5. **라이더 차감**: 회수를 포기한 때(`RECOVERY_ABANDONED`, fault RIDER) execution 이 그 라이더에게 **차감 예정**을 만든다. 금액 = 주문 **결제 금액 − 배달팁**(order 내부 조회 `approvedAmount`·`deliveryTip` — 예: 19,970 − 4,000 = 15,970, 봉투값은 포함). 하루 안에 회수에 성공하면 차감하지 않는다(오배송 배송 수행료를 막는 것은 지금처럼).
6. **이의 5일**: 차감 예정이 생기면 라이더 앱에 알리고 **5일** 동안 이의를 받는다. 이의가 오면 지원센터(RIDER_OPS)가 받아들이거나(차감 취소) 거절(차감 확정). 이의 없이 5일이 지나면 차감 확정.
7. **이월**: 확정된 차감은 다음 정산에서 뺀다. 그 정산금보다 크면 남은 금액을 **다음 정산으로 넘겨** 다 뺄 때까지 이어 간다(상한 없음). 남은 차감액은 라이더 백오피스·라이더 앱에 서버 값으로 보인다.
