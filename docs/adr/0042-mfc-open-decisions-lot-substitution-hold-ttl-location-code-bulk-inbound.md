# ADR-0042 MFC 미결 결정 4건 — 다른 LOT 대체, 예약 유지 10분, 위치 코드 계층형 문법, 일괄 입고 단계별 파일

- 상태: 승인 (2026-11-07, 사용자 — 문서 충돌·미결 4건에 대한 답)
- 결정 기록: MFC 문서 §6 Q-03·Q-04·Q-05(일부, IV-09 대체)·일괄 입고
- 관련: ADR-0040(재고 모델 v2), ADR-0041(상품별 소비기한 보장), `docs/business/flows/order-checkout-saga.md` D6-5

## 배경
MFC 를 더 만들기 전에 문서끼리 다르거나 미결인 항목이 넷 있었다.
1. **다른 LOT 대체**: OMS 문서 346행은 예약 LOT 이 막히면 "대체 확보 결과를 회신 … 성공은 같은 주문 예약 갱신" 이라 하고, MFC 문서 IV-09 는 "적격 대체 확보 시 D 감소/R 증가" 와 "임의 동일 SKU 다른 로트 대체 금지" 를 함께 적었다.
2. **예약 유지 시간**: OMS·Commerce 문서는 결제 전 예약 10분을 채택 설계로 적었지만, MFC 문서 Q-04 는 "검토안의 10분을 기본값으로 채택하지 않음, 미결 동안 결제 전 실제 접수 차단" 이다. 코드는 상수 10분이었다.
3. **위치 코드 형식**(Q-03): 계층형 주소 / 기존 주소+별칭 / 현장별 별칭 중 미결. 미결 동안 "실제 적재·피킹 위치 활성화 차단" 인데 코드는 자유 문자열로 쓰고 있었다. 6b 피킹(점원 단말 표시·라벨 스캔) 전에 필요하다.
4. **일괄 입고 파일 단위**: 다음 작업인 일괄 처리 API 에서 수령·품질검사·적치를 한 파일로 할지 단계별로 할지.

## 결정

### 1. 다른 LOT 대체 — 허용, 같은 상품·적격 기한만
- 예약 LOT 이 막히면(격리·파손·부족, IV-09) **같은 SKU(같은 상품·판매 단위)** 의 다른 LOT 으로 다시 잡을 수 있다. 고객 동의는 따로 받지 않는다.
- 대체 LOT 도 처음 배정과 **같은 적격 기준**을 통과해야 한다: 상품별 소비기한 보장(ADR-0041), 없으면 보관 유형 최소 잔여일, 배송 약속일 기준, 품질 NORMAL·판매 가능 수량. FEFO 순서도 같다.
- 다른 SKU(다른 상품)로 바꾸는 것은 여전히 고객 동의 없이 하지 않는다. 고객이 특정 LOT·기한 조건에 동의한 주문(마감 할인 등 — 지금 없음)은 그 조건 안에서만 대체한다.
- IV-09 의 "임의 동일 SKU 다른 로트 대체 금지" 는 "적격 기준·고객 동의 조건을 확인하지 않은 대체 금지" 로 읽는다. OMS 346행과 같은 뜻이 된다.
- 적용 시점: 예약 막힘(BLOCKED)·이행부족(D)을 만드는 IV-09 구현 때. 그때 6a 재시도 규칙 D6-5 의 "원래 예약만 다시 확인" 을 "같은 MFC 의 같은 SKU 적격 LOT 재확보" 로 넓힌다. 그 전까지 D6-5 는 그대로다.

### 2. 예약 유지 10분 — 확정, 설정값으로
- 결제 전 자원 점유(재고 예약·센터 여력·배송 슬롯) 유효시간은 **10분**. OMS·Commerce 문서의 채택 설계와 같다. 주문서 가격 동결 10분과는 시작 사건이 다른 별개 타이머다(Commerce 494행).
- 코드 상수를 설정 저장소 값으로 옮긴다: `pmart.orchestration.hold-ttl: PT10M`(사가가 요청에 넣는 값), `pmart.inventory.default-hold-ttl: PT10M`(요청에 값이 없을 때). 값이 없으면 새 결제 진입은 `CONFIG_REQUIRED`(0·무제한으로 대체하지 않음), 진행 중 사가는 값이 들어올 때까지 재개 대기.
- 계약 `ReserveInventoryRequest.ttlMinutes` 의 `default: 10` 은 지운다(생성 DTO 가 늘 10을 채워 설정을 우회하므로).
- Q-04 의 나머지(결제 결과 조회 종료·늦은 승인 처리 기한·조정자·보상 완료 조건)는 이미 원결과 조회 방식으로 구현돼 있어 이번 결정에 포함하지 않는다.

### 3. 위치 코드 — 계층형 고정 문법
- 선반·피킹(STORAGE·PICKING): `{온도대}-{구역}-{랙}-{단}-{칸}` — 예 `C-S1-03-2-04`.
  - 온도대 `A`(상온)·`C`(냉장)·`F`(냉동) = 위치의 temperatureZone.
  - 구역 = 영문 대문자 1 + 숫자 1(`S1`, `P1`) = areaCode(없으면 코드에서 채움).
  - 랙 2자리, 단 1~9, 칸 2자리.
- 그 밖의 구역: `{접두}-{온도대}-{번호 2자리}` — 예 `RCV-C-01`. 접두 `RCV` 수령, `PAK` 포장, `QRT` 격리, `DSP` 출고 대기, `RTN` 회수, `DSL` 폐기.
- 어기면 400 `LOCATION_CODE_INVALID`. **새 등록에만** 검사한다. 이미 등록된 자유 형식 코드는 바꿀 수 없으므로 그대로 쓰고, 바꾸려면 새 코드로 등록 → 재고 정정으로 옮김 → 옛 위치 CLOSED.
- 새 문법 코드는 속성 변경 때도 온도대·구역이 코드와 어긋나지 않게 검사한다.
- `location_id` 불변·코드는 표시용이라는 원칙(Q-03 설계 방향)은 그대로다. 코드 문자열 차이를 이동 거리로 쓰지 않는다(동선은 pickSequence·경로 데이터).
- Q-03 의 나머지(실제 배치·용량·혼재·통행 모델·폐쇄 절차)는 미결로 남는다.

### 4. 일괄 입고 — 단계별 파일
- 일괄 처리 API 의 입고는 **수령 · 품질검사 · 적치를 각각 다른 파일**로 올린다. 업무 문서에서 세 단계는 다른 사람이 다른 시점에 하는 일이고, 현장 사실은 하나씩 확정된다(IV-02·03·13).
- 다음 단계 양식을 서버가 채워 주는 기능(검토안 B+)은 이번 범위에 넣지 않는다.

## 대안
- LOT 대체 금지(같은 LOT 다른 위치만): 같은 상품이 선반에 있는데도 자동 취소된다. 택하지 않음.
- 고객 동의 후 대체: 즉시배송에서 응답 대기 흐름이 필요하다. 택하지 않음.
- 위치 코드 자유 + 구조 필드: 검토했으나 사용자가 계층형 고정 문법을 택했다.
- 일괄 입고 한 파일: 다른 사람·시점의 일을 한 번에 기록하게 된다. 택하지 않음.

## 결과
- mfc-location: `LocationCodes`(문법 검사), 계약 설명.
- order-orchestration·mfc-inventory: 유효시간 설정(`hold-ttl`·`default-hold-ttl`), pmart-config 와 시험 사본.
- LAN 시험 센터 MFC-SEED-01 의 옛 위치 40개(`RCV-01`, `A-01` 등)는 새 문법 위치로 옮긴다(등록 → 재고 정정 → 옛 위치 닫기, 시드 스크립트).
- 1·4 는 각각 IV-09 구현과 일괄 처리 API 때 코드에 들어간다.
