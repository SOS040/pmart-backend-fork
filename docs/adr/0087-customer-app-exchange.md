# ADR-0087 고객 앱 교환 접수 — 반품은 고객센터만, 교환은 재발송 흐름으로

- 상태: **승인** (2026-11-25, 사용자)
- 보탬: ADR-0052(오배송 회수·새 발송)·ADR-0069(전달 실패 재발송)의 **재발송 흐름을 교환에 쓴다**. ADR-0086(오배송 문의)은 그대로.
- 근거(사용자 2026-11-25, 클라이언트 BR-95 에 대한 답):
  - "교환은 고객쪽에서 신청 가능해, 반품은 고객센터 통해서만 가능해"
  - ① "기존 재발송 흐름 따르고"
  - ② "상온제품 교환은 바로 할 수 있고 냉장·냉동은 상담원 승인 뒤 할 수 있게"
  - ③ "변심 교환도 위랑 같은 흐름으로 가능. 교환비 있음"
  - ④ "재고 없으면 그건 주문 시 선택에 따라 취소할 수 있어(부분취소, 전체취소)"
  - ⑤ 라이더 요청사항은 재발송 배송 메모로 — "응"
- 계기: 고객 앱 BR-95(`pmart-clients docs/handoff/customer-app/2026-11-24-backend-customer-return-exchange.md`). 지금 claim 0.15.0 은 고객 RETURN 을 422 `UNSUPPORTED_ACTION` 으로 막고, EXCHANGE 는 직원도 422(구현 없음).

## 결정
1. **범위**: 고객 앱(고객 토큰, channel `CUSTOMER_APP`)은 **EXCHANGE 만** 접수한다. **RETURN 은 지금처럼 고객센터(직원)만** — 고객 토큰 RETURN 은 422 `UNSUPPORTED_ACTION` 그대로. 직원 EXCHANGE 도 같은 흐름으로 연다(상담원이 고객 대신 접수).
2. **진행 = 기존 재발송 흐름**: 교환이 진행되면 order-orchestration 재발송 사가(order `line-quantity-changes` reason `RESHIPMENT` — 오배송·전달 실패 재발송과 같은 길)로 **같은 SKU·같은 수량**을 새로 보낸다. 새 주문·새 결제는 만들지 않는다. 라이더가 새 상품을 건네며 기존 상품을 회수한다(배송 한 번). 회수품은 MFC 회수 검수(mfc-quality)로 — ADR-0086 결정 11 과 같다.
3. **승인**: 교환 품목이 **모두 상온(AMBIENT)이면 접수 즉시 진행**(APPROVED). **냉장·냉동(CHILLED·FROZEN) 품목이 하나라도 있으면 상담원 승인 뒤 진행**(접수 = 승인 대기, 상담원이 사진·사유를 보고 승인/거절). 온도대는 상품(SKU) 정본 값으로 판정한다.
4. **변심 교환도 받는다 — 같은 흐름, 교환비 있음**: 고객 사유(변심·주문 실수)도 결정 3 과 같게(상온 즉시·냉장냉동 승인) 진행하되 **교환비**를 받는다 — 지금 반품 회수비와 같은 FEE_PENDING → 고객 결제 → 진행 순서. 상품 문제·배달 문제(회사 잘못)는 교환비 없음. **교환비 금액은 정책값**(`pmart.claim.exchange-fee`, 설정 저장소) — 미설정이면 변심 교환만 CONFIG_REQUIRED(0원으로 진행하지 않는다).
5. **재고가 없으면 주문 때 고른 품절 처리대로**: 재발송할 재고가 없으면 그 주문의 `outOfStockPreference` 를 따른다 — `CANCEL_OOS_ONLY`(부분 취소) = 재고 없는 품목만 교환을 취소하고 그 품목 금액을 환불, 나머지는 교환 진행. `CANCEL_ALL`(전체 취소) = 이번 교환 전체를 취소하고 교환 품목 전부 환불. 취소된 교환의 교환비는 돌려준다.
6. **라이더 요청사항**: 고객이 쓴 회수·재배달 요청사항(각 50자)은 재발송 배송의 메모로 라이더 앱에 간다.
7. **교환 이유가 아닌 것**: "일부 안 왔어요"·"배달완료인데 안 왔어요"는 교환할 실물이 없어 교환 이유에서 빼고 ADR-0086 오배송·누락 문의로 보낸다.
8. **자격**: 품목마다 교환 가능 수량 = 전달 완료 수량 − 진행·완료 교환·반품 수량. 기한은 지금 claim 접수 기한 정책값을 그대로 쓴다(새 기한을 만들지 않는다). 상품·배달 문제 사유는 사진(1~3장)·상세 이유 필수.

## 남은 것(사용자)
- 교환비 금액(결정 4 — 정책값). 정해지기 전에는 변심 교환만 CONFIG_REQUIRED.

## 결과
- 고객은 앱에서 교환을 바로 신청하고, 상온은 바로·냉장냉동은 상담원 확인 뒤 같은 상품을 다시 받는다. 반품은 지금처럼 고객센터.
- 재발송 흐름을 다시 써서 새 배송 방식이 늘지 않는다. 재고 없음은 고객이 주문 때 고른 품절 처리 그대로라 따로 묻지 않는다.
