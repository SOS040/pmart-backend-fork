# ADR-0014 기준정보와 MFC 초기 재고는 정식 승인·반입 경로로만 넣는다

- 상태: 제안 (2026-10-28, 사용자 위임 결정 — 업무 구현 계획 D1·D2)
- 관련: `docs/architecture/implementation-plan.md` §4, ADR-0001·0002·0004, service-map(approval·product·pricing·center-master·delivery-serviceability·mfc-inbound·mfc-inventory)

## 배경
1단계 판매 루프를 시험하려면 상품·SKU·가격·센터·권역과 MFC 재고가 있어야 한다. 정본 서비스들은 이 값을 승인 결과(`ApprovalDecided`, BO-04~07) 또는 반입·검수 결과로만 바꾸도록 설계됐다. 개발 편의를 위해 DB 직접 적재나 승인 생략 경로를 두면, 승인 참조·버전·발효 이벤트가 없는 데이터가 생겨 이후 슬라이스(견적·재고 예약·감사)가 정식 경로와 다르게 동작한다.

## 결정
1. **기준정보는 승인 워크플로로만 넣는다.** 슬라이스 1에서 approval-service 를 최소 범위로 먼저 구현한다: 변경 요청 작성·제출 → 단일 승인자 결정(승인/반려) → `ApprovalDecided` 발행. 다단 결재·부분 승인·대행·일괄 변경은 이후로 미룬다.
   - 정본 서비스(product·pricing·center-master·delivery-serviceability)는 `ApprovalDecided` 를 구독하거나 승인 참조(`approvalId`)를 검증해 버전을 만든다. 승인 참조 없는 쓰기 경로는 만들지 않는다.
2. **MFC 초기 재고는 mfc-inbound 의 초기 보유 반입으로 넣는다**(1단계 범위 "초기 보유·회수 반입"). 반입 → 검수 → mfc-inventory 전기(`H+q`, 검수 후 `E+`)의 정식 순서를 따른다. 재고 조정 집행 경로를 초기 적재 용도로 쓰지 않는다.
3. **적재는 API 를 부르는 스크립트로 한다.** `deploy/lan/seed/`(가칭)에 시험용 기준정보·초기 재고를 정식 API 순서대로 호출하는 스크립트를 둔다. 운영자 토큰은 시험 서명키로 발급한다(LAN 전용, 비밀은 `.secrets/`). Flyway 마이그레이션에 업무 데이터를 넣지 않는다.

## 대안
- Flyway·SQL 로 시험 데이터 직접 적재: 빠르지만 승인 참조·버전·이벤트가 없다. 채택하지 않음.
- 정본 서비스에 "개발용 등록" 경로 추가: 승인 생략 경로가 운영 이미지에 남는다(이미지는 공개, ADR-0012). 채택하지 않음.
- 재고 조정 집행으로 초기 재고 적재: 조정은 손실·차이 처리용 승인 경로라 의미가 다르다. 채택하지 않음.

## 결과
- 슬라이스 1의 앞부분이 approval 최소 구현이 된다(계획 §3 1번의 첫 단계).
- 시험 데이터도 감사·승인 이력이 남아, 이후 운영 화면·감사 슬라이스(9)에서 그대로 쓸 수 있다.
- 적재 스크립트는 정식 API 의 회귀 시험 역할도 한다.
