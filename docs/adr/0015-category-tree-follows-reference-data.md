# ADR-0015 카테고리 트리는 업무 문서 정책 대신 제공된 참고 자료 구조를 따른다

- 상태: 제안 (2026-10-30, 사용자 결정)
- 관련: `docs/architecture/product-registration-design.md`, ADR-0001, Commerce 문서의 카테고리 확정 정책, `contracts/openapi/product-service.yaml`(`CategoryNode`)

## 배경
Commerce 문서는 고객 분류를 `[확정 정책]` 1·2단계(상위 30·하위 141·노출 경로 151)로 정했고, 계약 `CategoryNode.depth` 도 `[1, 2]` 다. 임시 백오피스 상품 등록에 쓰려고 사용자가 제공한 참고 자료(저장소 밖 `local-reference/`, 저작권 문제로 Git 제외)는 상위 32 > 하위 164 > 칩1 293 > 칩2 40 의 4단계이고, 노드마다 필터 패널(필터 그룹 1,409개)이 붙어 있으며 상위 노드는 섹션('맛있는것'·'편리한것')으로 나뉜다. 두 기준의 단계 수·개수가 다르다.

## 결정
- 사용자가 "업무 문서 확정 정책보다 넣어준 자료대로 적용"하도록 결정했다(2026-10-30). 카테고리 트리는 **참고 자료 구조**를 따른다.
  - 단계: TOP / SUB / CHIP1 / CHIP2 (최대 4단계, 순수 트리). TOP 은 `section` 을 가진다.
  - 노드별 필터 패널: 필터 그룹(이름·선택 방식 MULTIPLE/TOGGLE/MIXED·공통 여부)·옵션(화면 순서)·노드↔그룹(화면 순서).
  - `category_id` 는 참고 자료의 구조 id(`p03`, `p03-c01` …)를 쓴다. 참고 서비스의 실제 id 가 아니다.
- 유지하는 정책: 상품 다중 카테고리 + 대표 1개, 다중 노출이 SKU·장바구니 품목을 복제하지 않음, 트리 변경은 승인 경로(ADR-0014)·버전 관리.
- 트리·필터 **데이터 자체는 저장소에 넣지 않는다.** 적재 스크립트가 저장소 밖 참고 자료를 읽어 승인 API 로 넣는다(Flyway·소스에 포함 금지).
- 추천 바로가기(기획전·잘팔려요 등)는 프로모션·추천 전시라 1차에서 넣지 않는다.

## 대안
- Commerce 확정 정책(1·2단계)대로 두고 참고 자료를 상위·하위만 매핑: 사용자 결정과 다르다. 채택하지 않음.
- 칩 단계를 카테고리가 아닌 필터로만 표현: 참고 자료의 화면 구조(칩이 하위 분류)와 다르다. 채택하지 않음.

## 결과
- 계약 변경: `CategoryNode.depth`(1·2) → `level` + `section`, 필터 조회 경로 추가. 소비자(storefront·search·product-content)는 아직 구현 전이라 영향 없음.
- `docs/architecture/service-map.md` 의 product-service "카테고리(상위 30·하위 141·노출 경로 151)" 서술을 이 ADR 기준으로 바꾼다.
- Commerce 업무 문서의 카테고리 확정 정책 문구는 원문 작성자 영역이라 고치지 않았다. 이 ADR 이 설계 기준으로 대체한다.
