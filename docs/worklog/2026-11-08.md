## IV-08 집품 뒤 취소 (ADR-0046)
사용자 "그래 이제 마저해" — 2026-11-07 밤 남은 "대기" 두 가지(피킹 뒤 중지 PENDING, 결품 CANCEL_ALL·주문 전체 결품 상신)를 끝까지 자동으로.

| 서비스 | 바뀐 것 | 시험 |
|---|---|---|
| mfc-inventory (0.7.0) | `POST /internal/reservations/{id}/cancel-returns`(집품·포장분 CANCEL_RETURN_PENDING, 예약·이행부족 해제, RETURN_MISMATCH), MOVE = 취소 복귀(포장 위치 → 선반, QUARANTINED 가능) | `check` 통과 |
| mfc-fulfillment (0.3.0, V5) | 피킹 뒤 FULL 중지: 작업 종료·포장 INVALIDATED·출고 CANCELLED·RETURN 작업 → inventory cancel-returns → RESOLVED(packages STOPPED)·WorkStopResult, sweep. RETURN 실적 → inventory MOVE | `check` 통과(TaskFlowIT 3, CancelReturnRulesTest 3 등) |
| claim (V3) | 시스템 전체 취소 PREPARING·OUT_OF_STOCK, 활성 취소 = 현장 중지 있는 클레임만(결품 부분 환불 두 건 동시 진행 충돌도 해소), 전체 환불 = 승인액 − 앞선 환불 | `check` 통과(CancelClaimFlowIT 5) |
| order-orchestration | 결품 사가 CANCEL_ALL·전체 결품 → REQUEST_FULL_CANCEL(claim 시스템 전체 취소) | `check` 통과(ShortageSagaIT 2 등 41) |

이렇게 두었고 이유는(사용자 확인 없이 정한 작은 기본값):
- 피킹 뒤 **부분** 중지는 PENDING 유지 — 고객 부분 취소를 접수하지 않아 지금 들어올 길이 없다.
- 진행 중(재고 결과 대기) 실적·포장이 있으면 중지 준비를 미룬다 — 집품량이 확정돼야 복귀 대상이 맞는다(inventory 가 정확히 같아야 받음).
- 복귀 작업은 inventory 반영 뒤에야 READY — 그 전에 옮기면 재고가 거절한다.
- 결품 전체 취소 환불은 앞선 결품 부분 환불을 뺀 잔액(봉투·배달팁 포함) — 두 번 환불 방지, payment FULL 은 남은 잔액만 받는다.
- 재고가 취소 복귀를 거절하면 PENDING + last_error(운영자 확인) — 자동 보상하지 않는다.

남은 것: 6c 인계 fence, IV-11 실사·조사 보류 해소, IV-10 반품·폐기, CS(case-service), BO-12, 일괄 처리 API(보류), 실제 고객 주문 E2E(사용자 로그인·결제 필요).
