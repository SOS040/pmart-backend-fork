# 작업 일지 (worklog)

Claude Code가 수행한 작업의 "무엇을·왜·어떻게 검증했는지" 기록. **영역별 폴더의 날짜별 1파일** (`<영역>/YYYY-MM-DD.md` — 영역 platform·mfc·delivery, `docs/operations/pc-split.md`), 항목은 시간순. 여러 PC 가 같은 날 같은 파일에 쓰면 충돌하므로 2026-11-14 부터 나눴다. 2026-11-13 까지는 이 폴더 바로 아래 `YYYY-MM-DD.md`(그대로 둔다).

## 규칙
1. **커밋 없이 일지만 쓰지 않고, 일지 없이 커밋하지 않는다.** 커밋할 때 같은 커밋에 일지 항목을 포함한다(커밋 SHA는 푸시 직후 다음 항목 또는 같은 항목에 추기).
2. **실행한 검증만 적는다.** 실행하지 않은 테스트·빌드는 "미실행"으로 미결에 둔다.
3. 구조에 영향을 주는 결정은 일지에 적은 뒤 `docs/adr/`로 승격한다. 일지는 ADR을 대체하지 않는다.
4. 비밀정보·개인정보·토큰은 적지 않는다.
5. 자기 영역 파일에만 쓴다. 다른 영역에 영향을 준 일은 자기 일지에 `영향: <영역>` 으로 적는다.
6. **PR 기록(PC 1, 사용자 결정 2026-11-13)** — 다른 PC 의 PR 을 검토·병합하면 PC 1 일지(`platform/YYYY-MM-DD.md`)의 `## PR` 절에 한 건당 한 줄. 따로 PR 기록 파일을 두지 않는다(PR 설명·리뷰·병합은 GitHub 에, 작업 내용은 작성자의 영역 일지에 이미 있다). GitHub 에 없는 것만 적는다 — 검토 때 본 것·지적, **배포 상태**, 후속 할 일.
   ```markdown
   ## PR
   - PR #3 (mfc, YOO196) mfc/count-variance → 병합 a1b2c3d. 검토: 시험 실행 확인·계약 변경 없음. 배포: mfc-inventory-service LAN a1b2c3d. 후속: 없음
   ```
   - 배포 칸: `LAN <서비스> <sha>` / `배포 대기` / `해당 없음(문서)`. 나중에 배포하면 그날 일지에 같은 모양으로 `PR #3 배포: …` 한 줄(앞 줄은 고치지 않는다). 아직 안 내보낸 PR 은 `grep -rn "배포 대기" docs/worklog/platform/` 로 찾는다.
   - 닫고 병합하지 않은 PR 도 한 줄(`→ 닫음. 이유: …`).

## 항목 형식
```markdown
## HH:MM 제목
- 요청: 사용자의 말(요약 또는 인용)
- 한 일: 변경한 파일·범위
- 결정: 선택과 근거 (대안이 있었으면 한 줄)
- 검증: 실행한 명령과 결과 (통과/실패/경고 수)
- 미결: 남은 것, 가정, 확인 필요
- 커밋: SHA
```
