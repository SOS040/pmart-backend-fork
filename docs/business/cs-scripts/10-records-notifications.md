# 상담 기록, 고객 알림, 상담 분류, 라이더·MFC 전달

상담을 마칠 때 기록하고 알려야 하는 것들을 모았습니다.

- 문서 버전: 0.1
- 작성일: 2026-11-09

## 1. 상담 기록 [채택 설계]

- 상담은 백오피스의 **CS 접수**로 남기고, 처리가 이어지는 문제는 **사건(Case)** 으로 묶습니다(case-service).
- **접수는 명령이 아닙니다.** 상담 접수만으로 취소·환불·회수가 실행되지 않습니다. 실제 처리는 주문(OMS)·배송·결제 담당 흐름이 결과를 냅니다.
- **고객 동의는 따로 기록**합니다. 예: 주소를 라이더에게 알리는 동의, 교환·환불 선택.
- 같은 대상의 진행 중 접수가 있으면 새로 만들지 않고 기존 접수에 이어서 기록합니다.

반드시 기록할 것:

| 상황 | 기록 | 문서 |
|---|---|---|
| 모든 취소 요청 | 취소 사유, 요청 시각, 주문 단계 | [02](02-order-cancel.md) |
| 주문자 본인이 아닌 상담 | 주문자와의 관계 | [01](01-common-greeting-identity.md) §2 |
| 배송 완료 미수령·오배송 | 원주소 확인 결과, 전달 사진 확인, 라이더 확인 결과(귀책 인정 여부·재전달 가능 여부), 잘못 간 주소 | [06](06-wrong-delivery.md) |
| 개인정보 전달 | 누구에게 무엇을 전달하는지, 동의 여부 | [06](06-wrong-delivery.md) §5 |
| 누락·오피킹·파손 | 상품·수량, 사진 여부, 고객 선택(교환/환불), 회수 필요 여부 | [07](07-missing-wrong-item.md), [08](08-damage-quality.md) |
| 반품·교환 | 사유, 수령 시각, 비용 안내 여부 | [09](09-return-exchange.md) |

## 2. 라이더·MFC 전달 [설계안]

| 상황 | 받는 쪽 | 내용 |
|---|---|---|
| 고객 요청 전달(배송 중) | 라이더 | 정해진 전달 경로로 요청 내용 — 배송지·연락처 변경은 받지 않음 |
| 회수 배차 요청 | 배송(관제) | 회수 사유, 회수 장소(원주소 또는 잘못 간 곳), 회수 뒤 처리(폐기·센터 반납) |
| 누락·오피킹·포장 불량 | MFC(센터 관리자) | 사건 연결 — 피킹·포장 과정 확인 |
| 취소 요청 | MFC | 주문 처리 흐름이 자동으로 출고 중지를 요청함 — 상담원이 따로 전화로 멈추게 하지 않음 |

- 라이더 지급·공제, MFC 재고 조정은 상담원이 정하지 않습니다. 사실과 결과만 기록합니다.

## 3. 고객 알림 [채택 설계]

- 주문 취소·부분 취소(결품)·환불·반품 진행 결과는 **앱 알림이 자동으로** 갑니다(notification-service). 상담 중 "결과는 앱 알림으로 안내드립니다"라고 말합니다.
- 고객이 끌 수 없는 거래 알림(취소·환불 결과 등)과 끌 수 있는 알림이 구분됩니다.
- **카카오 알림톡 등 문자 채널은 승인 전**입니다(`[결정 필요]`) — 승인되지 않은 채널로는 보내지 않습니다. 상담 뒤 문자로 링크(사진 제출·환불 수단 등록 등)를 보내는 절차는 아직 없습니다.

## 4. 상담 분류 [채택 설계]

고객 문의는 아래로 나눕니다(`Commerce-business-logic.md` §13.2).

| 분류 | 예 | 문서 |
|---|---|---|
| 지연 | 라이더 배정 지연, 배송 중 지연 | [05](05-delivery-delay.md) |
| 오배송 | 다른 주문 포장 수령, 주문하지 않은 사람이 받음 | [06](06-wrong-delivery.md) |
| 미수령 | 배송 완료인데 못 받음 | [06](06-wrong-delivery.md) |
| 누락 | 포장에 상품이 빠짐 | [07](07-missing-wrong-item.md) |
| 파손 | 깨짐·샘·포장 불량 | [08](08-damage-quality.md) |
| 품질 | 신선도·이물 등 | [08](08-damage-quality.md) |
| 기타 | 취소·반품·계정 등 | [02](02-order-cancel.md), [09](09-return-exchange.md) |

- "배송 완료인데 받지 못함"을 반품으로 분류하지 않습니다.
- 다른 사유로 다시 신고해도 같은 피해 수량을 중복 환불 대상으로 만들지 않습니다.

취소 사유(기록용):

| 사유 | 예 |
|---|---|
| 고객 요청 | 단순 변심, 주소를 잘못 입력해 다시 주문 |
| 배송 문제 | 장기 지연 |
| 센터 사정 | 결품(주문 처리 흐름이 자동 처리), 센터 운영 중지 |
| 결제 문제 | 결제 확인 실패 |

- 취소 사유 코드 목록은 백오피스 화면 기준으로 맞춰야 합니다(`[결정 필요]`).
