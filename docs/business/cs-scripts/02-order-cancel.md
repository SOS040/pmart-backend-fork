# 주문 취소 요청

고객이 주문 취소를 요청했을 때 주문 단계별 처리와 대본, 예약 시간 변경·주소 변경 문의, 재주문 안내입니다.

- 문서 버전: 0.1
- 작성일: 2026-11-09
- 관련 문서: 환불은 [03](03-refund-partial-cancel.md), 결품으로 일부만 취소된 경우는 [04](04-shortage.md)

## 1. 취소의 기본 [채택 설계]

- 취소 요청은 **접수**입니다. 접수 시각만으로 라이더 인계보다 앞섰다고 보지 않습니다. MFC 가 출고 중지 또는 실제 인계를 확정합니다(`OMS-business-logic.md` §8.4).
- 취소 진행 상태: 접수 → 출고 중지 확인 중 / 인계 확인 중 → 취소 처리 중 → 취소 완료 또는 취소 불가. 주문 상태(상품준비·배송)와 별개입니다.
- 출고 중지와 재고 복귀가 끝나도 **결제 취소 성공 전에는 환불 완료로 안내하지 않습니다.**
- 이미 라이더에게 인계된 수량은 취소가 아니라 **회수·반품**으로 안내합니다([09](09-return-exchange.md)).
- 취소 사유는 반드시 확인해 기록합니다([10](10-records-notifications.md) §4).

## 2. 주문 단계별 처리 [설계안]

| 주문 단계 | 처리 | 고객 안내 |
|---|---|---|
| 결제 확인 중 | 결제 결과가 나올 때까지 새 취소·재결제를 하지 않습니다 | "결제 결과 확인 중입니다. 결과가 나오면 앱 알림으로 안내드립니다." |
| 결제 완료 ~ 상품준비 전 | 고객이 앱에서 직접 취소 가능. 상담 접수도 가능 → MFC 작업 중지·예약 해제 확인 | "앱 주문 내역에서 바로 취소하실 수 있고, 원하시면 접수해 드리겠습니다." |
| 피킹·포장 중(상품준비 뒤) | 고객 앱 취소 불가. 상담 접수 → MFC 가 미인계분 출고를 멈추고 상품을 선반에 되돌림 | "이미 준비가 시작되어 준비를 멈출 수 있는지 확인 후 안내드립니다." |
| 라이더 인계 확인 중 | 인계 결과를 기다림. 새 취소를 반복 접수하지 않음 | "라이더 인계 여부를 확인 중입니다. 확인되면 안내드리겠습니다." |
| 인계·배송 중 | 출고 전 취소 불가 → 수령 뒤 반품으로 안내(또는 배송 문제면 해당 문서) | "상품이 이미 출발해 주문 취소 대신, 받으신 뒤 반품으로 도와드릴 수 있습니다." |
| 일부 포장만 인계됨 | 인계된 수량은 회수·반품, 인계 안 된 수량만 취소 심사 | 수량을 나눠 안내 |

- 피킹 뒤 취소된 상품은 MFC 가 원래 선반으로 되돌린 뒤 재고가 풀립니다(ADR-0046).

## 3. 고객 취소 대본 [설계안]

1. 인사·본인 확인([01](01-common-greeting-identity.md) §2)
2. 주문 확인: "취소 원하시는 주문이 000시, 000원 주문 맞으실까요?"
3. 사유 확인: "실례지만 취소하시는 사유를 여쭤봐도 될까요?"
4. 주문 단계 확인: "확인을 위해 잠시만 기다려 주시겠습니까?"
5. (상품준비 전·준비 중) "취소 요청 접수되었습니다. 상품 준비 상태 확인 후 취소가 진행되며, 결과는 앱 알림으로 안내드립니다. 결제 취소가 완료되어야 환불이 시작되는 점 참고 부탁드립니다."
6. (이미 출발) "상품이 이미 라이더에게 전달되어 출발한 상태라 주문 취소는 어렵습니다. 받으신 뒤 반품 접수로 도와드릴 수 있습니다." → [09](09-return-exchange.md)
7. 마무리([01](01-common-greeting-identity.md) §7)

## 4. 취소 때 함께 안내할 것 [확정 정책]

- **봉투값(주문당 100원 1회)은 전체 취소 시 전액 환불**합니다. 단순 변심 부분 취소에는 환불하지 않습니다(`OMS-business-logic.md` §5.2).
- 전체 취소와 결제 취소 성공 뒤, 사용한 쿠폰의 유효기간이 남아 있으면 쿠폰 복원을 한 번 요청합니다(설계안, 쿠폰은 1차 제외 — `OMS-business-logic.md` §10.1).

## 5. 고객 자율 취소 마감·상품준비 뒤 취소 [확정 정책]

- 고객은 주문이 **상품준비(피킹 시작) 전까지** 앱 주문 내역에서 스스로 취소할 수 있습니다(ADR-0052, 사용자 결정 2026-11-09).
- **상품준비 뒤에는 고객 요청으로 취소할 수 없습니다 — 고객 앱·고객센터 모두**(ADR-0060, 사용자 결정 2026-11-13 — ADR-0052 결정 2 의 "고객센터 접수 뒤 미인계 수량 취소"를 없앰). 고객센터는 취소를 접수하지 않고, **받은 뒤 반품·교환**으로 안내합니다.
- 라이더에게 인계된 뒤(픽업·배달 시작 뒤) 고객이 받기를 원하지 않으면 고객센터 경유 **회수 요청**입니다 — 회수비 9,000원 고객 부담(회사 잘못이면 면제), 환불은 회수품 검수 뒤(D-7, CL-1 — 접수 방법은 구현 때 정함).
- 고객 요청이 아닌 중지는 시스템 취소뿐입니다 — 결품(전체·부분, ADR-0049)은 그 상품만 자동 취소·환불되고 앱 알림으로 안내됩니다.
- 대본(상품준비 전 — 앱 안내): "상품 준비 시작 전이라 앱의 주문 내역에서 바로 취소하실 수 있습니다."
- 대본(상품준비 뒤): "이미 상품 준비가 시작되어 앱과 고객센터 모두 취소해 드릴 수 없습니다. 상품을 받으신 뒤 반품으로 도와드리겠습니다."

## 6. 예약 시간 변경 [확정 정책]

- 예약배달은 주문이 **상품준비** 상태가 되기 전까지 **예약 시간만** 바꿀 수 있습니다. 이미 준비가 시작된 사실이 확인되면 반영이 늦어도 변경을 막습니다(`OMS-business-logic.md` §4).
- 새 시간대·재고·현장 상태 검증을 통과해야 바뀝니다.
- 대본: "상품 준비 시작 전이라 예약 시간 변경 가능합니다. 원하시는 시간대 말씀해 주시겠습니까?" / (준비 시작) "이미 상품 준비가 시작되어 시간 변경이 어렵습니다. 불편 드려 죄송합니다."

## 7. 주소·연락처 변경 문의 [확정 정책]

- **결제 후 주소·연락처·요청 사항은 바꿀 수 없습니다**(`OMS-business-logic.md` §4).
- 대본: "결제 후에는 배송지와 연락처 변경이 어려운 점 양해 부탁드립니다. 다른 주소로 받으셔야 한다면 주문을 취소하시고 새 주소로 다시 주문해 주셔야 합니다."
  - 취소가 가능한 단계인지 §2 로 먼저 확인합니다.

## 8. 재주문 안내 [설계안]

- 고객 사정으로 취소 후 다시 주문하는 경우: 새 주문으로 진행되며 이전 주문의 요청 사항은 넘어가지 않습니다. "새로 주문하실 때 요청 사항에 꼭 다시 적어 주세요."
- 이전 주문의 취소·환불이 아직 확인 중이면 **새 주문과 별개로 진행**된다는 점을 안내합니다(같은 요청을 다시 접수하지 않음).
