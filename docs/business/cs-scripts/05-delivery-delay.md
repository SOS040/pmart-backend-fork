# 배송 지연

라이더 배정이 늦거나, 배송 중 고른 배송 시간대보다 늦어지는 경우의 대응입니다.

- 문서 버전: 0.1
- 작성일: 2026-11-09
- 관련 문서: 취소는 [02](02-order-cancel.md)

## 1. 지연의 기본 [확정 정책]

- **지연·배송 실패만으로 자동 환불하지 않습니다.** 고객 연락, 보관 가능성, 후속 조치·회수 여부를 판단합니다(`OMS-business-logic.md` §9).
- 고객 수령 사실이 없는데 시간이 지났다고 배송 완료로 처리하지 않습니다(자동 완료 없음, `domain-map.md` §3).
- 예상 도착 시간은 라이더 배정·도로 상황에 따라 바뀝니다. 지연이 생기면 지연 알림이 고객에게 갑니다.

## 2. 라이더 배정 지연 [설계안]

포장은 준비됐는데 라이더가 아직 배정되지 않은 경우입니다.

- (사과) "불편 드려 죄송합니다."
- (필수 안내) "라이더 배정이 늦어지고 있는 점 확인됩니다. 가까운 라이더를 계속 찾고 있으며, 배정되는 대로 안전하게 배송하겠습니다."
- 센터·관제에서 배정 상황을 확인할 수 있으면 확인 후 안내합니다. 확인 결과 없이 시간을 약속하지 않습니다.

## 3. 배송 중 지연 [설계안]

라이더가 배송 중인데 고른 시간대보다 늦는 경우입니다.

1. (사과) "기다리시게 해서 죄송합니다."
2. (확인 후) "기다려 주셔서 감사합니다. 예상보다 배송이 늦어지고 있는 점 확인됩니다. 예상 시간은 도로 상황 등에 따라 바뀔 수 있으며, 최대한 빠르게 전달되도록 하겠습니다."
3. (신선식품 걱정) "냉장·냉동 상품이 걱정되시는 마음 충분히 이해합니다. 보냉 포장 상태로 전달되며, 받으신 상품에 문제가 있으면 바로 연락 주시면 확인 후 도와드리겠습니다." → 품질 문제는 [08](08-damage-quality.md)

## 4. 지연 보상 [결정 필요]

- 쿠폰·프로모션은 1차 구현에서 제외되어 보상 쿠폰을 발급할 수 없습니다. 승인 없는 임의 보상금도 하지 않습니다(`BackOffice-business-logic.md` 금지 기능).
- 지연 시간에 따른 보상 여부·방식(쿠폰·적립금 도입 시 금액)은 정해야 합니다. 정하기 전에는 사과와 진행 안내만 합니다.

## 5. 장기 지연과 취소 요청 [결정 필요]

- "장기 지연"으로 볼 기준 시간과, 그때 상담원이 먼저 취소를 권할지는 정해지지 않았습니다.
- 고객이 취소를 원하면 주문 단계에 따라 처리합니다([02](02-order-cancel.md) §2):
  - 라이더 인계 전: 취소 접수 → 출고 중지 확인
  - 인계 후(배송 중): 출고 전 취소가 안 됩니다. 배송 문제로 기록하고 담당자(관제)에게 연결해 후속 조치를 판단합니다. 상담원이 즉시 환불을 약속하지 않습니다.
- 대본(인계 전): "기다리시게 해서 정말 죄송합니다. 원하시면 주문 취소 요청 접수해 드리겠습니다. 취소 결과는 앱 알림으로 안내드립니다."
- 대본(배송 중): "상품이 이미 라이더에게 전달되어 이동 중이라 바로 취소는 어렵습니다. 지연 상황을 담당 부서에 전달해 확인 후 안내드리겠습니다."

## 6. 라이더에게 전달 [설계안]

- 고객 요청(빨리 와 달라, 문 앞에 두어 달라 등)을 라이더에게 전달할 때는 정해진 전달 경로를 쓰고 상담 기록에 남깁니다([10](10-records-notifications.md) §2).
- 결제 후 배송지·연락처는 바뀌지 않습니다. 다른 주소로 가 달라는 요청은 받지 않습니다([02](02-order-cancel.md) §7).
