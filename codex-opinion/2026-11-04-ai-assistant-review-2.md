# ai-assistant-service 1차 계획 — Codex 2차 검토 (2026-11-04, 원문)

1. **재조회 API를 계약에 명시해 주세요.**
   응답 유실 후 `requestId`로 결과를 회수하는 시험은 있는데, A에는 POST만 있습니다. 조회 경로, 처리 중·완료·실패 응답, 404 조건을 정의해야 합니다. `X-Source-System`도 요청 헤더를 그대로 신뢰하지 말고 인증 주체가 사용할 수 있는 값인지 검증해야 합니다.

2. **멱등성 해시는 응답에 영향을 주는 `context`까지 포함해야 합니다.**
   같은 질문이어도 센터·업무 영역 등의 힌트가 다르면 검색 결과가 달라질 수 있습니다. 정규화한 질문과 허용된 context를 함께 해시하고, 정규화 규칙도 고정해 주세요.

3. **lease를 잃은 작업자의 완료·실패 처리를 모두 차단해 주세요.**
   완료 UPDATE의 `attempt` 조건은 좋습니다. 다만 갱신 건수가 0이면 해당 작업자가 만든 답변을 200으로 반환하면 안 됩니다. 현재 저장 상태를 다시 조회해 응답해야 합니다. 실패 UPDATE에도 동일한 선점 조건이 필요합니다. 처리 시간이 2분을 넘을 수 있다면 heartbeat 또는 명확한 시간 제한도 정해야 합니다.

4. **문장별 n-gram 겹침을 '근거 검증 완료'로 취급하면 안 됩니다.**
   "승인이 필요하다"와 "승인이 필요하지 않다"는 단어가 많이 겹쳐도 의미는 반대입니다. 숫자·조건·예외에서도 같은 문제가 생깁니다. 이는 보조 휴리스틱으로 명시하고, 생성 답변의 충실도는 미검증으로 남겨 주세요. 발췌 응답도 조건·예외·표 헤더를 함께 보존해야 합니다.

5. **문서 우선순위와 대체 관계가 실제 검색·응답에 적용되는 규칙을 추가해 주세요.**
   manifest에는 우선순위가 있지만 저장·검색 단계에서 어떻게 쓰는지가 빠져 있습니다. 현재 정책 질문에서 `SUPERSEDED`와 `EXCLUDED_FROM_PHASE1`을 어떻게 제외할지, 제안 문서만 발견했을 때 어떻게 표시할지 정해야 합니다. `SUPERSESSION_PROPOSED`와 함께 표시할 제안 문서의 ID도 보존해 주세요.

6. **고정된 스냅숏의 수명과 입력 일관성을 보장해 주세요.**
   요청이 참조하는 RETIRED 스냅숏은 처리 도중 삭제되면 안 됩니다. 파일 해시는 실제 청크 생성에 사용한 동일 바이트에서 계산해야 합니다. 색인 중 파일 변경을 허용할지, 감지 후 실패시킬지도 정의해 주세요.

7. **계약·스키마의 불일치를 먼저 정리해 주세요.**
   - 활성 스냅숏 부재 시 반환하는 422가 API 계약에 없습니다.
   - 보존 작업의 `FAILED`와 실제 상태인 `FAILED_RETRYABLE`이 다릅니다.
   - 원문 저장 옵션이 참조하는 `question` 열이 열 목록에 없습니다.
   - 첨부본의 `503 DEPENDEN…`, 색인 검증 `vi` 등이 잘려 있습니다. 원본 확인이 필요합니다.

이 항목들을 반영하면 **외부 호출 없는 local/fake 기준선 구현은 진행해도 좋겠습니다.** 다만 완료 보고에서 "구조·권한·멱등성 검증 완료"와 "실제 모델의 검색·답변 품질 검증 완료"를 구분하는 현재 방침은 유지해 주세요.
